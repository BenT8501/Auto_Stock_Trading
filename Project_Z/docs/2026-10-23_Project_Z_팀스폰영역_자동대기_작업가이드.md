# Project_Z 팀 스폰 영역 탐색·자동 대기 작업 가이드

작성일: 2026-10-23. 로컬 코드 기준: `9196cc7`.

이 문서는 직접 구현하기 위한 가이드다. 아래 코드는 아직 프로젝트 소스에 적용하거나 빌드하지 않았다. 네트워크 재접속 문제는 별도 보류 상태다.

새 클래스나 소스 파일은 만들지 않는다. 스폰 관련 선언은 기존 `Project_Z_MultiGameMode.h`에, 구현은 기존 `Project_Z_MultiGameMode.cpp`에 넣는다. Controller와 Widget도 기존 파일을 수정한다.

## 1. 이번에 바꿀 동작

**기존 팀 선택 UI와 입장 버튼은 유지한다. 이번 변경은 팀이 확정된 뒤 캐릭터를 생성할 위치를 찾는 기능이다.**

접속 → 기존 UI에서 Team A / Team B 선택 → 입장 버튼 → 서버 팀 선택 검증·저장 → 서버 스폰 대기열 등록 → 선택한 팀의 PlayerStart 중심 및 주변 빈 위치 탐색 → Pawn 생성·Possess → 로컬 HUD 전환.

| 구분 | 처리 |
|---|---|
| Team A / Team B 버튼, 선택 강조 표시 | 기존 동작 유지 |
| 입장 버튼과 팀 선택 요청 RPC | 유지. 서버가 승인한 뒤 스폰 요청 |
| 서버 팀 검증·PlayerState 팀 저장 | 기존 TrySelectPlayerTeam 사용 |
| 스폰 위치 선정 | 확정된 팀의 PlayerStart 중심부터 검사하고, 막혔으면 주변 탐색 |
| 모든 후보가 막힌 경우 | 팀을 유지한 채 자동 스폰 재시도. 다른 팀으로 변경하지 않음 |
| 수동 Retry 버튼 | 자동 재시도로 대체하여 숨김. 팀 선택·입장 버튼과는 별개 |

- 기존 TeamA/TeamB PlayerStart를 **영역 중심**으로 재사용한다. 인원수만큼 PlayerStart를 만들지 않는다.
- 중심이 막혔으면 주변 후보 위치를 검사한다.
- 영역 전체가 막혔으면 연결과 확정 팀을 유지하고 서버가 0.5초 간격으로 재시도한다.
- 팀 선택과 입장 요청을 마친 뒤 대기 중인 플레이어는 자리가 나면 추가 버튼 입력 없이 생성된다. 팀을 선택하기 전에는 자동 생성하지 않는다. 사망 후에는 확정된 팀을 유지하고 기존 RespawnDelay 이후 같은 경로를 사용한다.
- 벽을 삭제하거나 캐릭터를 강제로 겹쳐 생성하지 않는다.

유한한 영역이 완전히 점유된 경우 즉시 스폰은 보장할 수 없다. 해결 목표는 **혼잡이 접속 실패나 일회성 스폰 실패로 끝나지 않게 하는 것**이다. 이 예제는 평평하고 열린 팀별 스폰 구역 기준이다. 벽으로 나뉜 방·다층 공간까지 일반화한 탐색기는 아니다.

## 3. 1단계 — GameMode 헤더

기존 클래스 전체를 지우지 말고 다음 항목만 반영한다. include는 `.generated.h`보다 위에 둔다. 현재 CoreMinimal/TimerManager include는 이미 있다.

public에 기존 `RestartPlayer` 선언은 유지하고 다음을 추가한다.

```cpp
virtual APawn* SpawnDefaultPawnAtTransform_Implementation(
    AController* NewPlayer, const FTransform& SpawnTransform) override;
```

다음 두 사용자 override 선언은 제거한다. 대응하는 cpp 구현도 2단계에서 제거한다.

```cpp
virtual AActor* ChoosePlayerStart_Implementation(AController* Player) override;
virtual AActor* FindPlayerStart_Implementation(
    AController* Player, const FString& IncomingName) override;
```

protected에 추가한다.

```cpp
virtual bool UpdatePlayerStartSpot(AController* Player,
    const FString& Portal, FString& OutErrorMessage) override;
virtual void EndPlay(const EEndPlayReason::Type EndPlayReason) override;

UPROPERTY(EditDefaultsOnly, Category="Z|Spawn", meta=(ClampMin="0.1"))

UPROPERTY(EditDefaultsOnly, Category="Z|Spawn", meta=(ClampMin="1", ClampMax="8"))
int32 SpawnSearchRings = 4;

UPROPERTY(EditDefaultsOnly, Category="Z|Spawn", meta=(ClampMin="10.0"))
```

private에 추가한다.


대기열은 서버 GameMode 내부 데이터이므로 Replicated/UPROPERTY를 붙이지 않는다. 약한 참조로 Controller의 생존을 연장하지 않는다.

## 4. 2단계 — 기존 구현 정리

기존 `Project_Z_MultiGameMode.cpp`에서 다음과 같이 정리한다.

1. `RestartPlayer()` — 기존 함수 본문을 3단계 구현으로 교체한다. 같은 함수의 구현을 두 개 남기지 않는다.
2. `ChoosePlayerStart_Implementation()` — 구현 전체를 제거한다.
3. `FindPlayerStart_Implementation()` — 구현 전체를 제거한다.

이 과정에서 `SpawnBlocker` 태그의 액터를 Destroy하던 테스트 코드도 함께 사라져야 한다. 사용하지 않게 된 `Engine/StaticMeshActor.h` include도 제거한다.

`TrySelectPlayerTeam()`은 유지한다. 이 함수는 팀별 PlayerStart가 **존재하는지** 확인하고 팀을 저장한다. 지금 빈 자리인지까지 팀 선택 승인 조건으로 넣지 않는다.

`HandleStartingNewPlayer_Implementation()`의 미선택 팀 차단도 유지한다.

## 5. 3단계 — 기존 GameMode cpp에 스폰 구현 반영

대상은 기존 `Private/GameModes/Project_Z_MultiGameMode.cpp`다. 아래 코드는 cpp 전체를 대체하는 코드가 아니라, 이번에 추가하거나 교체할 부분이다.

1. 아래 include 목록 중 없는 항목만 파일 상단에 추가한다. 이미 있는 include와 다른 기능에 필요한 include는 유지한다.
2. 기존 `RestartPlayer()` 구현은 아래 구현으로 교체한다.
3. 나머지 새 함수 구현은 기존 함수 바깥, 예를 들어 cpp 맨 아래에 추가한다.
4. 생성자, PostLogin, Logout, HandleStartingNewPlayer, TrySelectPlayerTeam, HandlePlayerDeath 등 기존 함수는 유지한다. Logout과 HandlePlayerDeath의 부분 수정은 4단계에서 진행한다.

헤더에서 선언한 새 함수의 구현은 아래에 모두 포함되어 있다.

```cpp
#include "GameModes/Project_Z_MultiGameMode.h"
#include "Controllers/Project_Z_MultiPlayerController.h"
#include "PlayerStates/Project_Z_MultiPlayerState.h"
#include "GameFramework/Character.h"
#include "GameFramework/CharacterMovementComponent.h"
#include "GameFramework/PlayerStart.h"
#include "Components/CapsuleComponent.h"
#include "Engine/World.h"
#include "EngineUtils.h"
#include "CollisionQueryParams.h"
#include "CollisionShape.h"
#include "TimerManager.h"

bool AProject_Z_MultiGameMode::UpdatePlayerStartSpot(
    AController* Player, const FString& Portal, FString& OutErrorMessage)
{
    // 초기 접속 때는 Pawn 위치를 정하지 않는다.
    // 팀 선택 이후 RestartPlayer에서 위치를 결정한다.
    OutErrorMessage.Reset();
    if (!IsValid(Player))
    {
        OutErrorMessage = TEXT("Invalid player controller.");
        return false;
    }
    return true;
}

void AProject_Z_MultiGameMode::RestartPlayer(AController* NewPlayer)
{
    if (!HasAuthority() || !IsValid(NewPlayer) ||
        NewPlayer->GetWorld() != GetWorld() || IsValid(NewPlayer->GetPawn()))
    {
        return;
    }
    const auto* PS = NewPlayer->GetPlayerState<AProject_Z_MultiPlayerState>();
    if (!IsValid(PS) || !PS->HasAssignedTeam())
    {
        return;
    }

    const TWeakObjectPtr<AController> WeakPlayer(NewPlayer);
    if (!PendingSpawnControllers.Contains(WeakPlayer))
    {
        PendingSpawnControllers.Add(WeakPlayer);
        UE_LOG(LogTemp, Log, TEXT("[SpawnQueue] Added: %s"), *GetNameSafe(NewPlayer));
        if (auto* PC = Cast<AProject_Z_MultiPlayerController>(NewPlayer))
        {
            PC->NotifySpawnStatus(false);
        }
    }

    // 처리 중 재진입은 막고, 일반적인 요청은 즉시 한 번 시도한다.
    ProcessPendingSpawns();
    if (!PendingSpawnControllers.IsEmpty() &&
        !GetWorldTimerManager().IsTimerActive(SpawnRetryTimerHandle))
    {
        GetWorldTimerManager().SetTimer(SpawnRetryTimerHandle, this,
            &ThisClass::ProcessPendingSpawns,
            FMath::Max(0.1f, SpawnRetryInterval), true);
    }
}

bool AProject_Z_MultiGameMode::FindTeamSpawnTransform(
    AController* Player, FTransform& OutTransform)
{
    UWorld* World = GetWorld();
    if (!IsValid(World) || !IsValid(Player)) return false;
    const auto* PS = Player->GetPlayerState<AProject_Z_MultiPlayerState>();
    if (!IsValid(PS)) return false;

    FName TeamTag = NAME_None;
    if (PS->GetPlayerTeam() == EZPlayerTeam::TeamA) TeamTag = TEXT("TeamA");
    else if (PS->GetPlayerTeam() == EZPlayerTeam::TeamB) TeamTag = TEXT("TeamB");
    else return false;

    UClass* PawnClass = GetDefaultPawnClassForController(Player);
    const ACharacter* DefaultCharacter = PawnClass
        ? Cast<ACharacter>(PawnClass->GetDefaultObject()) : nullptr;
    const UCapsuleComponent* Capsule = DefaultCharacter
        ? DefaultCharacter->GetCapsuleComponent() : nullptr;
    const UCharacterMovementComponent* Movement = DefaultCharacter
        ? DefaultCharacter->GetCharacterMovement() : nullptr;
    if (!IsValid(Capsule) || !IsValid(Movement)) return false;

    const float Radius = Capsule->GetScaledCapsuleRadius();
    const float HalfHeight = Capsule->GetScaledCapsuleHalfHeight();
    const float Step = FMath::Max(SpawnSearchStep, Radius * 2.0f + 10.0f);
    const int32 Rings = FMath::Clamp(SpawnSearchRings, 1, 8);
    const FCollisionShape Shape = FCollisionShape::MakeCapsule(Radius, HalfHeight);
    const FCollisionResponseParams Responses(Capsule->GetCollisionResponseToChannels());
    FCollisionObjectQueryParams GroundObjects;
    GroundObjects.AddObjectTypesToQuery(ECC_WorldStatic);

    for (TActorIterator<APlayerStart> It(World); It; ++It)
    {
        APlayerStart* Anchor = *It;
        if (!IsValid(Anchor) || Anchor->PlayerStartTag != TeamTag) continue;
        const FVector Origin = Anchor->GetActorLocation();
        FCollisionQueryParams Query;
        Query.AddIgnoredActor(Anchor);

        // 중심에서 바깥쪽으로 중복되지 않는 사각형 테두리를 탐색한다.
        for (int32 Ring = 0; Ring <= Rings; ++Ring)
        for (int32 X = -Ring; X <= Ring; ++X)
        for (int32 Y = -Ring; Y <= Ring; ++Y)
        {
            if (FMath::Max(FMath::Abs(X), FMath::Abs(Y)) != Ring) continue;
            const FVector Offset(X * Step, Y * Step, 0.0f);
            const FVector TraceStart = Origin + Offset + FVector(0, 0, 100);
            const FVector TraceEnd = Origin + Offset - FVector(0, 0, HalfHeight + 100);
            FHitResult FloorHit;
            if (!World->LineTraceSingleByObjectType(
                FloorHit, TraceStart, TraceEnd, GroundObjects, Query)) continue;
            if (FloorHit.bStartPenetrating ||
                FloorHit.ImpactNormal.Z < Movement->GetWalkableFloorZ()) continue;

            const FVector Location = FloorHit.ImpactPoint + FVector(0, 0, HalfHeight + 3);
            // 다른 층이나 높은 장애물 위는 후보에서 제외한다.
            if (FMath::Abs(Location.Z - Origin.Z) > 50.0f) continue;
            if (World->OverlapBlockingTestByChannel(Location, FQuat::Identity,
                Capsule->GetCollisionObjectType(), Shape, Query, Responses)) continue;

            OutTransform = FTransform(
                FRotator(0, Anchor->GetActorRotation().Yaw, 0), Location);
            return true;
        }
    }
    return false;
}

void AProject_Z_MultiGameMode::ProcessPendingSpawns()
{
    if (!HasAuthority() || bProcessingPendingSpawns) return;
    TGuardValue<bool> ProcessingGuard(bProcessingPendingSpawns, true);
    // 생성 중 콜백에서 원본 배열이 바뀌어도 순회가 깨지지 않게 복사한다.
    const TArray<TWeakObjectPtr<AController>> Snapshot = PendingSpawnControllers;
    for (const TWeakObjectPtr<AController>& WeakPlayer : Snapshot)
    {
        if (!PendingSpawnControllers.Contains(WeakPlayer)) continue;
        AController* Player = WeakPlayer.Get();
        const auto* PS = IsValid(Player)
            ? Player->GetPlayerState<AProject_Z_MultiPlayerState>() : nullptr;
        if (!IsValid(Player) || Player->GetWorld() != GetWorld() ||
            !IsValid(PS) || !PS->HasAssignedTeam())
        {
            PendingSpawnControllers.Remove(WeakPlayer);
            continue;
        }

        if (!IsValid(Player->GetPawn()))
        {
            FTransform SpawnTransform;
            if (!FindTeamSpawnTransform(Player, SpawnTransform)) continue;
            RestartPlayerAtTransform(Player, SpawnTransform);
        }

        APawn* Pawn = Player->GetPawn();
        if (IsValid(Pawn) && Pawn->GetController() == Player)
        {
            PendingSpawnControllers.Remove(WeakPlayer);
            UE_LOG(LogTemp, Log, TEXT("[SpawnQueue] Spawned: %s Pawn=%s Location=%s"),
                *GetNameSafe(Player), *GetNameSafe(Pawn), *Pawn->GetActorLocation().ToString());
            if (auto* PC = Cast<AProject_Z_MultiPlayerController>(Player))
            {
                PC->NotifySpawnStatus(true);
            }
        }
    }
    if (PendingSpawnControllers.IsEmpty())
    {
        GetWorldTimerManager().ClearTimer(SpawnRetryTimerHandle);
    }
}

APawn* AProject_Z_MultiGameMode::SpawnDefaultPawnAtTransform_Implementation(
    AController* NewPlayer, const FTransform& SpawnTransform)
{
    if (!IsValid(NewPlayer) || !GetWorld()) return nullptr;
    UClass* PawnClass = GetDefaultPawnClassForController(NewPlayer);
    if (!PawnClass) return nullptr;
    FActorSpawnParameters Params;
    Params.Owner = NewPlayer;
    Params.Instigator = GetInstigator();
    Params.ObjectFlags |= RF_Transient;
    Params.SpawnCollisionHandlingOverride =
        ESpawnActorCollisionHandlingMethod::DontSpawnIfColliding;
    return GetWorld()->SpawnActor<APawn>(PawnClass, SpawnTransform, Params);
}

void AProject_Z_MultiGameMode::RemovePendingSpawn(AController* Player)
{
    PendingSpawnControllers.RemoveAll([Player](const TWeakObjectPtr<AController>& Entry)
    {
        return !Entry.IsValid() || Entry.Get() == Player;
    });
    if (PendingSpawnControllers.IsEmpty())
    {
        GetWorldTimerManager().ClearTimer(SpawnRetryTimerHandle);
    }
}

void AProject_Z_MultiGameMode::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
    GetWorldTimerManager().ClearTimer(SpawnRetryTimerHandle);
    PendingSpawnControllers.Empty();
    Super::EndPlay(EndPlayReason);
}
```

`UpdatePlayerStartSpot`에서는 의도적으로 Super를 호출하지 않는다. 이 프로젝트의 최초 접속에 Portal/PlayerStart 위치 선정을 요구하지 않고, 팀 선택 이후에 위치를 결정하기 때문이다. 추후 포털 지정 이동·Seamless Travel을 지원하면 별도 검토한다.

`RestartPlayerAtTransform()`이 Pawn 생성 후 Possess 경로를 담당하므로 여기서 따로 Possess를 호출하지 않는다. 실제 생성에도 충돌 거부 정책을 적용하여 탐색 이후의 충돌을 다시 확인한다. SpawnDefaultPawnAtTransform을 BP에서 override한 경우 해당 override를 제거하거나 이 부모 구현을 호출하도록 정리해야 한다.

같은 서버 게임 스레드에서 한 명씩 즉시 생성한다. 다음 사람의 탐색은 이미 생성된 Pawn의 충돌을 보므로 현재 구조에는 별도 위치 예약 시스템을 추가하지 않는다. 비동기 생성으로 바꾸면 예약이 필요하다.

## 6. 4단계 — 종료와 사망 경로 연결

기존 `Logout()` 맨 앞에 아래 한 줄을 추가한다. 기존 로그와 `Super::Logout(Exiting)`은 유지한다.

```cpp
RemovePendingSpawn(Exiting);
```

`HandlePlayerDeath()`의 기존 지연 타이머는 유지한다. 다음 조건만 교체한다.

```cpp
// 기존
if (WeakDeadCharacter.IsValid() && CurrentPawn != WeakDeadCharacter.Get())
// 변경
if (CurrentPawn != WeakDeadCharacter.Get())
```

이미 다른 Pawn을 소유했다면 이전 사망 콜백이 새 Pawn을 삭제하지 못하게 한다. 기존 `UnPossess → Destroy → RestartPlayer`는 유지한다. 이제 RestartPlayer가 실패해도 대기열에 남아 자동으로 다시 시도한다.

기존 `RestartPlayer completed` 로그는 즉시 생성 완료처럼 보이므로 `Respawn requested`로 문구를 바꾼다. 실제 완료 기준은 `[SpawnQueue] Spawned` 로그와 Pawn 소유 여부다.

## 7. 5단계 — Controller의 팀 선택 결과 연결

기존 `HandleTeamAClicked`, `HandleTeamBClicked`, `HandleEnterClicked`와 `RequestTeamSelection()` 호출 흐름은 유지한다. 입장 버튼에서 서버에 팀 선택을 요청하고, 서버의 `TrySelectPlayerTeam()`이 성공한 경우에만 `RestartPlayer()`로 이어진다. BeginPlay에서 팀을 자동 확정하거나 팀 선택 화면을 건너뛰는 코드를 추가하지 않는다.

헤더 public에 다음 일반 함수를 **새로 선언**한다. 서버 GameMode가 직접 호출하며 RPC 자체는 아니다.

```cpp
void NotifySpawnStatus(bool bSpawnSucceeded);
```

cpp에 구현을 추가한다. 기존 Client RPC를 재사용한다.

```cpp
void AProject_Z_MultiPlayerController::NotifySpawnStatus(bool bSpawnSucceeded)
{
    if (!HasAuthority()) return;
    ClientTeamSelectionResult(true, bSpawnSucceeded,
        FText::FromString(bSpawnSucceeded
            ? TEXT("Entering game...")
            : TEXT("Waiting for a free spawn position. Entry will retry automatically.")));
}
```

`ServerRequestTeamSelection_Implementation()` 전체를 교체한다.

```cpp
void AProject_Z_MultiPlayerController::ServerRequestTeamSelection_Implementation(
    EZPlayerTeam RequestedTeam)
{
    UWorld* World = GetWorld();
    AProject_Z_MultiGameMode* GameMode = World
        ? World->GetAuthGameMode<AProject_Z_MultiGameMode>() : nullptr;
    if (!IsValid(GameMode))
    {
        ClientTeamSelectionResult(false, false,
            FText::FromString(TEXT("GameMode is unavailable.")));
        return;
    }
    FText FailureReason;
    if (!GameMode->TrySelectPlayerTeam(this, RequestedTeam, FailureReason))
    {
        ClientTeamSelectionResult(false, false, FailureReason);
        return;
    }
    GameMode->RestartPlayer(this);
}
```

이 함수 마지막에서 즉시 GetPawn 결과로 실패 메시지를 다시 보내지 않는다. 대기 시작과 생성 성공 알림은 GameMode가 각각 보낸다.

`ClientTeamSelectionResult_Implementation()` 전체를 교체한다. RPC 선언은 기존 것을 그대로 쓴다.

```cpp
void AProject_Z_MultiPlayerController::ClientTeamSelectionResult_Implementation(
    bool bAccepted, bool bSpawnSucceeded, const FText& Message)
{
    if (!IsLocalController() || bInitialEntryCompleted) return;
    bRequestPeding = false;
    TeamSelectionMessage = Message;
    if (bAccepted) bTeamSelectionAccepted = true;
    RefreshInitialEntryState();
}
```

`bSpawnSucceeded` 인자는 기존 RPC 시그니처 호환을 위해 남긴다. RPC가 Pawn 복제보다 먼저 도착할 수 있으므로 이것만 보고 HUD로 전환하지 않는다. 기존 RefreshInitialEntryState가 로컬 Pawn과 BeginPlay를 확인한 뒤 EnterGamePlayUI를 호출하는 흐름을 유지한다.

## 8. 6단계 — 수동 재시도 경로 정리

이 단계의 제거 대상은 **Retry 버튼의 수동 스폰 재시도 처리만**이다. `Button_TeamA`, `Button_TeamB`, `Button_Enter`와 각각의 클릭 함수·바인딩은 유지한다. 팀 확정 전에는 기존처럼 선택·입장할 수 있고, 확정 후 스폰 대기 중에는 재선택을 막는다.

Controller 헤더와 cpp에서 다음을 제거한다.

- `RequestInitalSpawnRetry()` 선언·구현.
- `ServerRetryInitialSpawn()` UFUNCTION 선언과 `_Implementation()` 구현.
- 변수 `bInitialSpawnPedding`, `LastInitialSpawnRetryTime`, `bCanRetryInitialSpawn`.
- RequestTeamSelection/EnterGamePlayUI 등에서 `bCanRetryInitialSpawn = false`로 대입하는 줄.

`RefreshInitialEntryState()`의 다음 호출을 교체한다.

```cpp
// 기존
TeamSelectionWidget->ApplySelectionState(Message, false, bCanRetryInitialSpawn);
// 변경
TeamSelectionWidget->ApplySelectionState(Message, false, false);
```

`ZTeamSelectionWidget`에서 아래를 제거한다.

1. 헤더의 `HandleRetrySpawnClicked()` 선언 및 UFUNCTION.
2. cpp의 `HandleRetrySpawnClicked()` 구현.
3. NativeOnInitialized의 Retry 버튼 OnClicked.AddDynamic 연결 줄.

이번 단계에서는 `Button_RetrySpawn` BindWidget과 WBP의 해당 버튼은 남겨도 된다. `ApplySelectionState()`의 세 번째 인자가 항상 false이므로 버튼을 숨기는 기존 동작을 사용한다. 이로써 기존 WBP 바인딩을 깨뜨리지 않는다. 별도 Blueprint 클릭 이벤트가 있다면 거기서도 옛 재시도 함수를 호출하지 않도록 제거한다.

현재 리스폰 시에는 `bInitialEntryCompleted` 때문에 팀 선택 창을 다시 열지 않는다. 서버 자동 재시도는 동작하지만 별도의 사망 후 대기 문구 UI는 이 가이드 범위에 포함하지 않는다.

## 9. 7단계 — 에디터 설정

1. TeamA/TeamB PlayerStart를 각각 팀의 열린 바닥 위에 배치한다. **Player Start Tag**에 TeamA/TeamB를 지정한다. Actor Tags가 아니다.
2. PlayerStart 중심 높이는 정상 캐릭터 캡슐 중심 높이와 비슷하게 맞춘다. 예제는 탐색 결과의 중심 높이가 기준점에서 50cm 이상 달라지면 제외한다.
3. GameMode BP의 SpawnSearchRings=4, SpawnSearchStep=120, SpawnRetryInterval=0.5를 시작값으로 둔다. 기본 후보는 중심 포함 최대 81개, 정사각형 반폭 약 480cm다. 캡슐 지름이 크면 Step이 자동으로 더 커진다.
4. 이 정사각형과 캡슐 여유 공간 전체가 해당 팀의 열린 스폰 구역 안에 들어가게 배치한다. 팀 구역끼리 겹치거나 벽 너머 다른 방에 후보가 생기지 않게 한다. 이 예제는 경로 연결성 검사까지 하지는 않는다.
5. 바닥은 WorldStatic으로 충돌 검출되고 Pawn을 Block해야 한다. 캐릭터 Capsule은 Query 충돌 활성화, Object Type=Pawn, Pawn 응답=Block이어야 이미 생성된 캐릭터를 다음 탐색에서 피한다.
6. 런타임에 캡슐 크기를 CDO 기본값과 다르게 바꾸지 않는지 확인한다. 예제는 기본 캐릭터 캡슐 크기로 검사한다. 이동 플랫폼·절벽 가장자리·좁은 돌출 바닥은 테스트 구역으로 사용하지 않는다. 중앙 바닥 Trace만으로 캡슐 전체 지지면을 보장하지는 않는다.
7. DefaultPawnClass는 현재 FPS 캐릭터 BP로 유지한다. 다른 BP 코드에서 RestartPlayerAtPlayerStart/직접 SpawnActor로 이 대기열을 우회하지 않게 확인한다.

## 10. 구현 후 검증 순서

각 단계 코드 반영이 끝난 뒤 사용자가 빌드하고 아래를 검증한다. 이 문서를 작성하면서 빌드·PIE는 실행하지 않았다.

| 순서 | 조건 | 성공 기준 |
|---|---|---|
| 1 | 빈 A/B 영역 | 선택 팀 영역에 생성, HUD 전환 |
| 1-1 | 접속 후 팀 선택·입장 버튼을 누르지 않음 | 기존 팀 선택 UI 유지, 전투 Pawn 자동 생성 없음 |
| 1-2 | B 선택 후 입장 버튼 | 서버에 B 저장 후 B PlayerStart 중심 또는 주변에서 생성 |
| 2 | 영역 중심만 장애물로 차단 | 같은 영역의 주변 빈 후보에 생성 |
| 3 | 같은 팀에 여러 명 입장 | 서로 겹치지 않음. 기존 캐릭터가 새 캐릭터에 밀려 튀지 않음 |
| 4 | 해당 영역 전체 차단 | 접속·팀 선택 유지, 대기 문구, 재시도 버튼 숨김, Pawn 없음 |
| 5 | 4 상태에서 서버가 장애물 제거 | 버튼 없이 다음 재시도에 생성. 클라이언트에서만 장애물을 지운 것은 유효한 시험이 아님 |
| 6 | 대기 중 해당 클라이언트 종료 | 대기열 제거, 나중에 유령 Pawn 생성 없음 |
| 7 | 사망 후 영역 차단 | 기존 지연 뒤 자동 스폰 대기, 공간 확보 후 리스폰 |
| 8 | A 영역 차단/B 영역 비어 있음 | A 플레이어를 B 영역으로 보내지 않음 |
| 9 | TeamB PlayerStart 자체 누락 | 서버 접속은 유지. B 선택에는 설정 누락 안내, A 선택 가능 |
| 10 | 연속 Enter 입력 및 반복 스폰 요청 | 팀 재선택/중복 Pawn 생성 없음 |

전체 차단 시험은 한 PlayerStart 캡슐만 덮으면 부족하다. 주변 후보 영역 전체를 충분히 높은 충돌 상자로 막아야 한다. 기존 SpawnBlocker 자동 삭제 코드는 제거되어 있어야 한다.

대기열이 비면 타이머도 종료된다. 기본값·팀별 중심 1개·최대 6명 기준 한 번에 최대 약 486개 바닥 후보를 조사할 수 있으므로 현재 소규모 검증용 설정이다. 중심 개수·반경을 무작정 늘리지 않는다.

설정이 잘못되어 빈 자리가 영원히 없으면 계속 대기한다. 이를 네트워크 재접속 실패와 혼동하지 않는다. 원격 서버 연결 자체가 성립하지 않는 문제는 별도 기록의 보류 항목이다.

## 11. 참조와 구현 상태

Unreal의 GameMode에는 초기 시작점 갱신과 Transform 기반 재시작·Pawn 생성 확장 지점이 있다. 이 가이드는 그 경로를 사용하고, 대기열·팀 영역 검색 정책은 프로젝트에서 직접 구현한다.

- [Epic AGameModeBase API](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/AGameModeBase)
- [Epic UpdatePlayerStartSpot API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/GameFramework/AGameModeBase/UpdatePlayerStartSpot?application_version=5.5)
- [Epic SpawnDefaultPawnAtTransform API](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/GameFramework/AGameModeBase/SpawnDefaultPawnAtTransform?application_version=5.5)

API 페이지 버전과 프로젝트 UE5.7 설치 헤더가 다를 수 있으므로 실제 override 선언은 설치된 GameModeBase.h를 최종 기준으로 확인한다. 예제 구현은 현재 프로젝트 구조에 맞춰 작성했으나 컴파일·실행 완료 코드로 표시하지 않는다.

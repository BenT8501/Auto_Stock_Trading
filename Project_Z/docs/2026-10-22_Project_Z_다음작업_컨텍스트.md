# Project_Z 다음 작업 컨텍스트

작성일: 2026-10-22

## 1. 현재 목표

Listen Server 기반 최대 6인, 2팀 FPS의 핵심 기능을 2026-10-28까지 기능 우선으로 완성한다. Hitscan은 사용하지 않고 서버 권한 Projectile 충돌 방식만 유지한다. 무기 위치, 손 정렬, 카메라 감각 등의 연출 조정은 핵심 기능 검증 이후로 미룬다.

## 2. 이번 작업에서 확인된 완료 항목

- 접속 후 A/B 팀 수동 선택, 서버 승인 및 PlayerState 저장
- 팀별 최초 스폰 기본 흐름
- `WBP_TeamStatus`를 통한 상단 `TEAM A / TEAM B` HUD 표시
- `WBP_PlayerTeamMarker`를 통한 원격 플레이어 절대 소속 마커 표시
- 팀 정보 변경에 따른 마커 갱신
- 카메라와 대상 사이 WorldStatic/WorldDynamic 차폐 시 마커 숨김
- 장애물을 벗어나 시야가 확보되면 마커 재표시
- C++ UHT 및 Project_ZEditor Win64 Development 빌드 성공

사용자가 Listen Server PIE에서 팀 HUD, 팀 마커, 벽 가림 및 재표시까지 직접 확인했다.

## 3. 에디터 연결 상태

### 전투 HUD

- `WBP_TeamStatus` 부모: `ZTeamStatusWidget`
- 내부 변수: `Border_Root`, `Text_TeamA`, `Text_Score`, `Text_TeamB`
- `WBP_FPS_HUD`에 자식 위젯으로 배치
- 자식 이름: `TeamStatus`, `Is Variable` 활성화
- `BP_Project_Z_MultiPlayerController.HUDWidgetClass`: `WBP_FPS_HUD`

미표시 문제의 실제 원인은 Controller가 `WBP_TPS_HUD`를 생성하고 있던 것이었다. 사용자가 `WBP_FPS_HUD`로 수정해 해결했다.

### 플레이어 마커

- `WBP_PlayerTeamMarker` 부모: `ZPlayerTeamMarkerWidget`
- 내부 변수: `Border_Team`, `Text_Team`
- `BP_ZCharacter_FPS.Team Marker Widget Class`: `WBP_PlayerTeamMarker`
- C++ `TeamMarkerHUDComponent`가 Screen Space로 표시하며 0.25초 간격으로 팀·차폐 상태를 갱신한다.

## 4. 구현됐지만 아직 런타임 완료 판정을 하지 않은 항목

### 팀 점수

- `AProject_Z_MultiGameState`에 `TeamAScore`, `TeamBScore`가 복제된다.
- 서버 `RegisterPlayerKill`은 적 팀 처치에만 공격자 팀 점수를 1 증가시킨다.
- 자살, 공격자 불명, 같은 팀 처치는 점수를 주지 않는다.
- HUD의 `Text_Score` 갱신 코드는 연결되어 있다.
- 실제 처치 후 호스트와 게스트의 동시 갱신은 아직 검증하지 않았다.

### 팀별 사망·리스폰 회귀

- 기존 사망·리스폰 기능은 앞선 작업에서 확인했으나 수동 팀 선택 및 신규 HUD·마커 연결 이후 종합 재검증이 필요하다.
- 리스폰 후 PlayerState 팀 유지, 올바른 팀 PlayerStart, HP·탄약·입력·HUD 복구를 확인해야 한다.

## 5. 다음 작업 순서

### 1순위: 팀 점수 검증

1. Listen Server 2인으로 호스트와 게스트를 서로 다른 팀에 배치한다.
2. 호스트가 게스트를 처치하고 양쪽 화면 점수가 동일하게 `1 : 0` 또는 `0 : 1`로 바뀌는지 확인한다.
3. 역할을 바꿔 게스트가 호스트를 처치하고 양쪽 점수가 동일한지 확인한다.
4. 같은 팀 조합에서 처치해도 점수가 증가하지 않는지 확인한다.
5. 이상 발생 시 `RegisterPlayerKill`, Projectile의 DamageSource 전달, GameState 점수 복제 순으로 추적한다.

### 2순위: 팀별 사망·리스폰 종합 검증

1. 사망 시 이동·발사·재장전이 제한되는지 확인한다.
2. 리스폰 후 기존 PlayerState 팀이 유지되는지 확인한다.
3. A팀은 TeamA 태그, B팀은 TeamB 태그 PlayerStart에서 생성되는지 확인한다.
4. HP, 탄약, 입력, 상단 HUD, 팀 마커가 정상 복구되는지 확인한다.
5. 리스폰 후에도 누적 팀 점수가 유지되는지 확인한다.
6. 호스트/게스트 역할을 바꿔 반복한다.

### 3순위: 접속 관리

- 플레이어 퇴장 시 GameState PlayerArray와 팀 인원이 정상 정리되는지 확인
- 새 접속은 팀을 다시 선택하며 이전 퇴장자의 팀을 복원하지 않는지 확인
- 최대 6인 허용 및 7번째 접속 거절 처리 구현·검증
- 접속 중복 요청과 정원 초과 요청의 서버 검증

### 4순위: 네트워크 종합 검증

- PIE 6인 기본 접속·이동·전투
- 패킷 지연·손실 환경에서 발사, 피해, 탄약, 재장전, 사망, 리스폰, 팀 점수 확인
- 중복 피해·중복 탄약 차감·중복 점수 증가 여부 확인
- 오류 수정 후 2인 기본 회귀 테스트 재실행

## 6. 아직 결정되지 않은 정책

- 아군 피해 허용 또는 차단
- 목표 점수 및 승리 조건
- 라운드 종료와 점수 초기화 시점
- 팀 마커 거리 제한 여부

정책이 정해지기 전에는 기존 동작을 임의로 변경하지 않는다. 현재 아군 피해는 허용하지만 아군 처치 점수는 증가하지 않도록 구현되어 있다.

## 8. 작업 시 주의사항

- 작업 트리에 C++, Blueprint, 맵, 문서 변경이 함께 남아 있으므로 초기화하거나 되돌리지 않는다.
- `python/__pycache__` 변경은 이번 기능과 무관하므로 수정하거나 삭제하지 않는다.
- 화면에 보인다는 사실과 네트워크 양쪽 값이 동일하다는 사실을 분리해 검증한다.
- 코드 구현, 빌드 성공, PIE 검증을 각각 별도 상태로 기록한다.
- 다음 작업 시작점은 팀 점수의 호스트·게스트 양쪽 갱신 검증이다.

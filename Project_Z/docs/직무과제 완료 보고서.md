3. 성과 (기대효과 대비 달성한 내용 작성)
이번 과제를 통해 Unreal Engine의 멀티 플레이 기능을 구현 하면서 서버와 클라이언트의 역할, RPC를 통한 요청 처리, Replication을 통한 상태 전달 흐름을 이해 하고 적용 하는 경험을 하였습니다. 특히 호스트에서는 정상 동작 하지만 게스트에서 문제가 발생하는 상황을 해결 하는 과정을 통해 입력 처리와 서버의 상태 변경 및 클라이언트의 반영을 구분 하여 확인 하는 방법을 익혔습니다. 
 GameMode, GameState, PlayerState, PlayerController, Character등에 각각 팀 선택, 전투, 리스폰등의 기능을 적용 하였고 이를 통해 각 클래스에 어떤 기능과 데이터를 배치 해야 하는지, 캐릭터가 사망 하고 다시 생성 할 대 어떤 상태를 유지 해야 하는지 판단 할 수 있게 되었습니다. 
무기 데이터와 공통 전투 처리를 분리 하고 총기교체 쉴드 아이템 획득 기능을 연결 하면서 기존 구조를 활용해 기능을 확장 할 수 있게 되었습니다. 이를 통해 UI 와 애니메이션을 게임 상태에 연결 하여 C++과 blueprint 설정 사이의 관계를 이해 하고 연동 하는 능력을 높였습니다.

5-1. 아키텍처 구현을 통한 역량 향상

수행 내용
• GameMode에서 팀 선택·스폰 처리, GameState에 점수·시간 저장, PlayerState에 팀 저장, Controller에서 입력 요청·로컬 UI 관리
• 캐릭터 사망 이후에도 팀을 유지하도록 PlayerState 사용
• 로컬 UI와 서버 판정, 상태 복제 시점 구분
• ZCharacterBaseMulti에서 발사·재장전·피해 처리, ZCharacter_FPS에서 카메라·조준·무기 습득 처리

향상된 실무 역량
Unity 네트워크 개발 경험을 Unreal Engine 클래스 구조에 맞춰 적용 하는 경험을 확보 실무에서 Unreal Engine 기반의 네트워크 개발 역량을 향상 하였습니다.
서버에서 처리 할 기능과 클라이언트에 공유할 정보를 구분하여 멀티플레이 구조를 구성 하였습니다.
플레이어의 입력, 서버에 요청, 상태 표시를 구분하여 화면에 표시할 수 있게 구조를 만들었습니다.

주요 클래스 및 함수
• AProject_Z_MultiGameMode: TrySelectPlayerTeam(), RestartPlayer(), RegisterPlayerKill()
• AProject_Z_MultiGameState: TeamAScore, TeamBScore, MatchPhase
• AProject_Z_MultiPlayerState: PlayerTeam, OnRep_PlayerTeam()
• AProject_Z_MultiPlayerController: RequestTeamSelection(), CreateHUDWidget()
• AZCharacterBaseMulti: 공통 전투·재장전·피해·사망
• AZCharacter_FPS: FPS 입력·ADS·무기 습득·마커 표시

팀 입장 흐름
팀 UI → Controller 서버 RPC → GameMode 검증 → PlayerState 팀 저장 → 주변 스폰 탐색 → Pawn 준비 후 HUD 전환
※ 공간 부족 시 대기열 등록 후 기본 0.5초 간격 재탐색

3. 성과 (기대효과 대비 달성한 내용 작성)
기존 Unity 멀티플레이 개발 경험을 바탕으로, Unreal Engine의 RPC·Replication·RepNotify와 네트워크 프레임워크를 활용해 Listen Server 기반 팀 FPS를 구현했습니다. 플레이어 한 명이 서버 역할도 수행하는 클라이언트–서버 방식으로 접속·팀 선택·전투·리스폰·경기 종료·재경기·퇴장 및 재접속을 연결하고 검증했습니다.

클라이언트의 발사·재장전·아이템 습득 요청을 서버에서 검사하고, 서버가 확정한 HP·쉴드·탄약·팀·점수·시간을 각 클라이언트에 전달하도록 구성했습니다. GameMode·GameState·PlayerState·PlayerController·Character의 역할에 맞춰 기능과 데이터를 배치하고, 일반 리스폰에서 유지할 팀 정보와 재경기에서 초기화할 경기 상태를 구분했습니다.

호스트와 게스트의 이동·피격·HUD 동작 차이와 재경기·재접속 문제를 입력, 서버 검사·값 변경, 상태 복제, 로컬 표시 단계로 나누어 확인하고 수정했습니다. 이를 통해 기존 네트워크 개발 경험을 Unreal 환경으로 확장하고, Unreal의 클래스 구조와 복제 방식에 맞춰 멀티플레이 기능을 구현·검증하며 상태 불일치의 원인을 추적하고 설명하는 경험을 확보했습니다.

5-1. 아키텍처 구현을 통한 역량 향상

수행 내용
• GameMode에서 팀 선택·스폰 처리, GameState에 점수·시간 저장, PlayerState에 팀 저장, Controller에서 입력 요청·로컬 UI 관리
• 캐릭터 사망 이후에도 팀을 유지하도록 PlayerState 사용
• 로컬 UI와 서버 판정, 상태 복제 시점 구분
• ZCharacterBaseMulti에서 발사·재장전·피해 처리, ZCharacter_FPS에서 카메라·조준·무기 습득 처리

향상된 실무 역량
• 기존 Unity 네트워크 개발 경험을 Unreal의 GameMode·GameState·PlayerState·Controller 구조에 맞춰 적용
• 서버 결정값·전체 공유값·캐릭터 교체 후 유지값 구분 및 Unreal 클래스별 배치
• Unreal RPC·Replication을 활용한 클라이언트 요청 → 서버 검사·결과 결정 → 각 화면 반영 구성

주요 클래스 및 함수
• AProject_Z_MultiGameMode: TrySelectPlayerTeam(), RestartPlayer(), RegisterPlayerKill()
• AProject_Z_MultiGameState: TeamAScore, TeamBScore, MatchPhase
• AProject_Z_MultiPlayerState: PlayerTeam, OnRep_PlayerTeam()
• AProject_Z_MultiPlayerController: RequestTeamSelection(), CreateHUDWidget()
• AZCharacterBaseMulti: 공통 전투·재장전·피해·사망
• AZCharacter_FPS: FPS 입력·ADS·무기 습득·마커 표시

팀 입장 흐름
팀 UI → Controller 서버 RPC → GameMode 검증 → PlayerState 팀 저장 → 주변 스폰 탐색 → Pawn 준비 후 HUD 전환
※ 공간 부족 시 대기열 등록 후 기본 0.5초 간격 재탐색

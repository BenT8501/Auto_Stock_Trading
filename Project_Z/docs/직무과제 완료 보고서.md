5-1. 아키텍처 구현을 통한 역량 향상

수행 내용
• GameMode에서 팀 선택·스폰을 처리하고, GameState에 경기 점수·시간을, PlayerState에 팀 정보를 저장했습니다. Controller에서는 입력 요청과 로컬 UI를 관리했습니다.
• 캐릭터 사망 이후에도 팀을 유지하도록 PlayerState 사용
• 로컬 UI와 서버 판정, 상태 복제 시점 구분
• 발사·재장전·피해 처리는 ZCharacterBaseMulti에 모으고, FPS 카메라·조준·무기 습득은 ZCharacter_FPS에서 처리했습니다.

향상된 실무 역량
• 서버에서 결정할 값, 모든 플레이어에게 전달할 값, 캐릭터가 교체돼도 유지할 값을 구분하여 저장할 클래스를 선택하는 경험을 쌓았습니다.
• 클라이언트가 요청하고 서버가 결과를 결정한 뒤 각 화면에 반영되는 과정을 이해하고 연결했습니다.
• 기존 전투 코드를 활용할 부분과 FPS에만 추가할 부분을 구분하여 수정했습니다. 실무에서 수정할 클래스와 다른 기능에 미치는 영향을 설명하는 데 활용할 수 있습니다.

주요 클래스 및 함수
• AProject_Z_MultiGameMode: TrySelectPlayerTeam(), RestartPlayer(), RegisterPlayerKill()
• AProject_Z_MultiGameState: TeamAScore, TeamBScore, MatchPhase
• AProject_Z_MultiPlayerState: PlayerTeam, OnRep_PlayerTeam()
• AProject_Z_MultiPlayerController: RequestTeamSelection(), CreateHUDWidget()
• AZCharacterBaseMulti: 공통 전투·재장전·피해·사망
• AZCharacter_FPS: FPS 입력·ADS·무기 습득·마커 표시

팀 입장 흐름
팀 UI → Controller 서버 RPC → GameMode 검증 → PlayerState 팀 저장 → 주변 스폰 탐색 → Pawn 준비 후 HUD 전환
※ 공간 부족 시 대기열 등록 후 기본 0.5초 간격 재탐색


5-2. 전투·투사체 구현을 통한 역량 향상
수행 내용
• FPS 이동·달리기·ADS와 서버 속도 반영
• 서버 발사 검증: 생존·경기·재장전·탄약·쿨다운
• 총구 위치·카메라 조준점으로 발사 방향 계산
• 샷건 다중 발사·확산, 발사체 풀 획득·초기화·반환
• 쉴드 우선 피해, HP 감소, 사망·점수·리스폰 연결

향상된 실무 역량
• 입력 → RPC → 서버 판정 → 충돌 → 상태 복제 추적
• 객체 재사용 시 충돌 무시·타이머·피격 기록 초기화
• 호스트·게스트 동작 차이를 단계별로 조사
주요 함수와 처리 내용
• Fire(), ServerRequestFire_Implementation(), FirePrimaryProjectile()
• AcquireActor(), ReleaseActor(), OnAcquiredFromPool_Implementation()
• HandleProjectileOverlap(), RuntimeHitActors, RuntimeRemainingPierceCount
• HandleReloadInput(), ServerRequestReload_Implementation(), ComplateServerReload()
• ReceivePlayerDamage(), CurrentShield, OnPlayerDeath()

무기를 획득했을 때의 동작
• 동일 DataAsset 습득 시 최대 3회 10% 강화·탄약 유지
• 다른 무기로 교체 시 강화 초기화·기본 탄약 적용
• 재장전 결과는 서버 타이머로 확정
※ 샷건 발사체가 일부만 생성됐을 때 탄약과 피해를 어떻게 처리할지는 추가 검토가 필요합니다.

5-3. UI·상호작용 구현을 통한 역량 향상
수행 내용
• Controller에서 소유 플레이어의 HUD 생성·전환
• HP·쉴드·탄약, 팀 점수·경기 시간 표시
• 피격 대상 HP Bar 및 시야 차폐를 고려한 팀 마커
• 팀 선택·스폰 대기·경기 결과·ESC 메뉴 연동
• 픽업 소비 성공 조건과 지점별 재생성 타이머 구성

향상된 실무 역량
• Widget 클래스·인스턴스·데이터 준비 단계 구분
• 상태 복제와 로컬 표시의 갱신 시점 추적
• 서버가 결정한 HP·쉴드·점수를 UI에서 읽어 표시하도록 연결했습니다. UI 미표시 문제와 데이터 갱신 문제를 나누어 조사하고 설명하는 경험을 쌓았습니다.
주요 UI·아이템 클래스 및 함수
• CreateHUDWidget(), HUDWidgetClass, HUDWidget
• UZStateHUDWidget::RefreshCurrentStatus(): HP·쉴드·탄약
• UZTeamStatusWidget::RefreshTeamStatus(): 점수·시간·팀
• UpdateTeamMarkerPresentation(): 차폐 검사·팀 관계
• AZShieldPickupActor::OnOverlapBegin(): 서버 회복 확인 후 소비
• SpawnInitialShieldPickups(), SchedulePickupRespawn()
• PickupSpawnOptionBag: 무기·쉴드 4종 셔플 백

아이템 생성과 화면 갱신 방법
• 픽업은 소비한 지점만 기본 10초 뒤 재생성
• HP·탄약 등의 값은 캐릭터와 GameState에 저장하고, UI에서는 해당 값을 읽어 표시합니다.
• 현재 UI는 Tick에서 값을 조회하는 부분과 변경 이벤트를 받는 부분을 함께 사용합니다.

5-4. 데이터·네트워크 구현을 통한 역량 향상
수행 내용
• WeaponDataAsset으로 공격력·탄약·발사체·조준 설정 분리
• 서버 RPC에서 무기 픽업·발사·재장전 조건 재검증
• PlayerState·GameState·캐릭터 상태 복제와 RepNotify 연동
• 팀 선택 승인과 Pawn 실제 생성 가능 여부 분리

향상된 실무 역량
• 에셋에 저장할 기본 공격력·탄약 설정과 플레이 중 바뀌는 탄약·강화·쉴드 값을 구분하여 관리하는 방법을 익혔습니다.
• 클라이언트에서 요청했더라도 서버에서 대상·생존 여부·탄약·발사 간격 등을 다시 검사한 뒤 적용하도록 구현했습니다.
• 팀 값 전달, Pawn 생성, UI 준비가 서로 다른 순서로 진행될 수 있음을 이해하고 확인했습니다. 실무에서 네트워크 상태와 화면 표시가 어긋나는 문제를 분석하는 데 활용할 수 있습니다.
※ 기존 TPS의 GAS 적 피해 구현을 FPS 신규 성과로 중복 산정하지 않음
주요 데이터·복제 항목
• UZWeaponDataAsset: 무기 기본 능력치·메시·소켓·조준
• CurrentWeaponData / OnRep_CurrentWeaponData(): 무기 표현
• SameWeaponDamageBonusStacks: 생명 단위 강화 상태
• PlayerTeam / OnRep_PlayerTeam(): 팀 상태 복제
• TeamAScore / TeamBScore: 팀 점수 공유
• RemainingMatchSeconds / MatchPhase / WinningTeam: 경기 정보
• CurrentShield / OnRep_CurrentShield(): 보호막 갱신
• bProjectileActive / OnRep_ProjectileActive(): 풀 재사용 표현

처리 흐름: 서버에서 요청 검사·값 변경 → 상태 복제 → 각 클라이언트 UI·캐릭터 표현 갱신


5-5. 경기 진행·리스폰 구현을 통한 역량 향상
수행 내용
• Waiting → Playing → Finished 경기 단계 구성
• 양 팀 인원 존재 시 시작, 기본 120초 제한 시간
• 종료 시 점수 비교, 한 팀 이탈 시 기권 승리 처리
• 사망 후 기본 3초 지연 리스폰·팀 유지
• 팀 시작점 주변 탐색 및 혼잡 시 대기·재시도

향상된 실무 역량
• 서버에서 경기 시간을 진행하고 승패를 결정하는 처리와 각 플레이어가 메뉴·결과를 보는 처리를 나누어 구현했습니다.
• 캐릭터가 제거되거나 새로 생성될 때 예약된 작업이 어떤 객체를 참조하는지 확인하고, 팀은 유지하면서 새 캐릭터의 전투 값은 초기화하는 방법을 익혔습니다.
• 다음 경기를 시작하려면 이전 타이머·발사체·아이템·팀·UI를 정리해야 함을 파악했습니다. 실무에서 게임 진행 단계를 추가할 때 이전 작업과 상태가 남는지 검토하는 데 활용할 수 있습니다.

※ 접속을 유지한 전체 재경기 초기화는 진행 중인 작업이며, 완료 성과에 포함하지 않습니다.

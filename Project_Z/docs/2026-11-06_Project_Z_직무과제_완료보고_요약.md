# FPS 멀티플레이 직무과제 완료 보고 요약

## 주요 구현 결과

| 구분 | 구현 내용 |
|---|---|
| 접속·팀 선택 | 방 생성, 호스트 주소 접속, 서버 팀 승인, 팀별 스폰·공간 부족 시 재시도 |
| 이동·전투 | FPS 이동·조준·달리기, 서버 발사 검사, Projectile 충돌·피해·풀 재사용 |
| 무기·쉴드 | 권총·소총·샷건 교체·강화, 서버 탄약·재장전 처리, 쉴드 획득·피해 흡수 |
| UI·경기 | HP·쉴드·탄약·팀 마커·점수·시간 표시, 사망·리스폰, 경기 결과 |
| 재경기·퇴장 | 접속 유지 초기화, 참가자 준비 확인, 팀 재선택, 퇴장·재접속 |

## 구체적으로 쌓은 경험과 지식

기존 Unity 멀티플레이 경험을 Unreal의 RPC·복제·클래스 구조에 적용하며 다음 내용을 익힘.

| 구현 사례 | 쌓은 경험 | 익힌 Unreal 네트워크 지식 |
|---|---|---|
| 게스트 달리기 수정 | 로컬·서버의 이동 속도 적용 경로 확인, RPC로 달리기 시작·종료 전달 | 로컬 MaxWalkSpeed 변경은 서버에 자동 적용되지 않음. CharacterMovement의 이동 처리와 별도 달리기 상태 전달을 구분해야 함 |
| 무기 교체·화면 갱신 | 서버에서 무기를 교체하고, 서버의 직접 호출과 클라이언트 OnRep로 메시·애니메이션 갱신 | 변수 전달과 표현 갱신은 별도 처리. C++ 서버에서 복제 값을 변경해도 서버 OnRep는 자동 호출되지 않음 |
| 팀 유지·리스폰 | 사망한 Pawn 제거 후 같은 팀으로 새 Pawn 생성, HP·탄약 등 전투 값 초기화 | Pawn과 PlayerState의 수명이 다름. 일반 리스폰 후 유지할 팀은 PlayerState에, 새 생명마다 초기화할 값은 캐릭터에 보관 |
| 재경기 준비 확인 | 초기화 번호·팀 미선택·Pawn 제거 확인 후 서버에 준비 응답, 응답 대기 중 경기 시작 보류 | 서버 처리 완료와 클라이언트 반영 완료는 다름. RPC 도착만으로 다른 객체의 복제 완료를 가정할 수 없음 |

## 검증 및 전체 흐름

접속·팀 선택·전투·상태 표시·사망·리스폰·경기 종료·재경기·퇴장 후 재접속 동작 확인.

**방 생성·접속 → 팀 선택 → 전투·아이템 습득 → 사망·리스폰 → 시간 종료·결과 → 재경기 또는 퇴장**

※ 검증 완료는 개발자 실행 확인 기준. 최대 6인은 목표 인원이며 실제 검증 인원·횟수·지연 수치는 기록에 따라 별도 기재.


직무 과제 요점 정리
Unreal Engine 네트워크 환경에서 서버와 클라이언트의 처리 구조와 네트워크 기능을 활용 방식을 학습하고 이를 이용하여 멀티플레이 환경에서의 기능들을 설계 및 구현 하는 경험하였습니다.
기존 Unity 멀티플레이 작업 경험을 바탕으로 Unreal Engine 에서 클래스 구조와 RPC, 상태 복제를 실제 기능에 적용 Unreal Engine 에서의 동작 차이를 확인 수정 하는 경험을 하였습니다.

구체 적인으로 익힌 내용과 적용한 내용
서버와 클라이언트에서 기능이 실행 되는 방식 설명
발사, 재장전, 아이템 습득 요청을 Server RPC로 전달 하고 서버에서 검사 처리
달리기의 경우 입력 키를 누르면 즉시 로컬에서는 이동속도를 변경 하고 달리기 시작 상태를 Server RPC로 전달하고 서버에서도 달리기 시작상태와 이동속도 변경 하고입력 키를 놓으면 달리기 종료 상태 전달 양쪽의 걷기 속도로 복귀 합니다.
서버에서 변경한 값이 각 클라이언트 화면에 전달 반영 되는 과정
서버에서 캐릭터의 탄약, 쉴드, 무기 정보, PlayerState의 팀 정보, GameState의 점수시간 등 변경한 값을 Unreal의 상태 복제 기능으로 클라이언트에 반영 하고, HUD, UI에서 해당 값을 조회 하여 표시 합니다.
Unreal 멀티플레이 환경에서 오류 분석 및 수정
호스트와 게스트의 달리기 상태 이상 오류 분석 및 수정 및 팀 생성 및 Pawn 스폰 상황에서 충돌 오류로 인한 스폰 실패 오류 수정 서버의 팀 승인과 캐릭터 생성 단계를 나눠 캐릭터의 생성 조건을 나누어 오류를 수정 하는 경험을 하였습니다.

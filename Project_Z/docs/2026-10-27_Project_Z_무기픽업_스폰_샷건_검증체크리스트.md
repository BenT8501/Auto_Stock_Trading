# Project_Z 무기 픽업·공용 스폰·샷건 검증 체크리스트

- 검증 예정일: 2026-10-27
- 대상: FPS Listen Server 멀티플레이
- 권장 환경: 호스트 1명 + 게스트 1명 이상
- 목적: 2026-10-26 추가 구현 사항의 기능·복제·회귀 오류 확인

## 1. 검증 전 준비

- [ ] Unreal Editor를 완전히 종료한다.
- [ ] Visual Studio에서 `Project_ZEditor / Development Editor / Win64` 전체 빌드를 성공시킨다.
- [ ] 에디터를 다시 실행한다.
- [ ] 테스트 맵의 9개 TargetPoint에 `ShieldSpawn` Actor Tag가 있는지 확인한다.
- [ ] `SKM_Shotgun` 총열 끝에 `Muzzle` 소켓이 저장됐는지 확인한다.
- [ ] `DA_Weapon_Shotgun.MuzzleSocketName`이 정확히 `Muzzle`인지 확인한다.
- [ ] PIE를 Listen Server, 플레이어 2명 이상으로 실행한다.

판정 원칙:

- 호스트에서만 정상인 경우 실패다.
- 게스트에서만 정상인 경우 실패다.
- 화면상 정상처럼 보여도 서버·클라이언트의 탄약, 피해, 무기 상태가 다르면 실패다.

## 2. 시작 무기와 리스폰

- [ ] 호스트와 게스트 모두 최초 스폰 시 권총을 장착한다.
- [ ] 권총 Mesh와 권총 Animation Blueprint가 적용된다.
- [ ] 권총 기본 탄약과 HUD 탄약 값이 일치한다.
- [ ] 소총이나 샷건을 든 상태에서 사망해도 리스폰 시 권총으로 초기화된다.
- [ ] 리스폰 후 동일 무기 강화 스택이 0으로 초기화된다.

## 3. TargetPoint 공용 픽업 스폰

- [ ] 게임 시작 약 1초 뒤 태그가 붙은 9개 TargetPoint에 픽업이 모두 생성된다.
- [ ] 한 포인트에 픽업이 2개 이상 겹쳐 생성되지 않는다.
- [ ] 쉴드·권총·소총·샷건이 무작위 위치에 배치된다.
- [ ] 셔플 백 특성상 최초 9개가 한 종류로만 몰리지 않는다.
- [ ] 호스트와 게스트 화면에서 같은 위치에 같은 픽업이 보인다.
- [ ] 픽업 외형과 실제 습득 결과가 일치한다.

확인 로그:

```text
[PickupSpawn] Initial batch complete. Points=9 Spawned=9 Active=9
```

## 4. 개별 10초 재생성

- [ ] 한 픽업을 습득하면 해당 픽업이 호스트와 게스트 양쪽에서 제거된다.
- [ ] 다른 8개 슬롯은 영향을 받지 않는다.
- [ ] 습득 시점부터 약 10초 뒤 같은 TargetPoint에 새 픽업이 생성된다.
- [ ] 여러 포인트를 시간차로 습득하면 각 포인트가 개별 타이머로 재생성된다.
- [ ] 재생성 아이템 종류가 고정 순서가 아니라 무작위로 결정된다.
- [ ] 재생성 시점에 플레이어가 포인트를 점유하면 겹쳐 생성하지 않고 이후 다시 시도한다.

확인 로그:

```text
[PickupSpawn] Respawn scheduled. Point=... Delay=10.0
```

## 5. 무기 습득과 교체

- [ ] 권총 상태에서 소총을 습득하면 소총으로 교체된다.
- [ ] 소총 상태에서 샷건을 습득하면 샷건으로 교체된다.
- [ ] 샷건 상태에서 권총을 습득하면 권총으로 교체된다.
- [ ] 교체 시 Mesh, Animation Blueprint, 발사 방식과 탄약이 새 무기 데이터로 바뀐다.
- [ ] 습득한 필드 무기가 모든 클라이언트에서 제거된다.
- [ ] 호스트와 게스트 모두 `F` 입력으로 정상 습득할 수 있다.
- [ ] 무기 교체 도중 재장전 상태가 남지 않는다.

## 6. 동일 무기 공격력 강화

- [ ] 권총을 든 상태에서 권총을 먹으면 교체가 아니라 강화된다.
- [ ] 소총을 든 상태에서 소총을 먹으면 강화된다.
- [ ] 샷건을 든 상태에서 샷건을 먹으면 강화된다.
- [ ] 1스택은 해당 무기 기본 공격력의 `+10%`다.
- [ ] 최대 3스택, 총 `+30%`까지만 증가한다.
- [ ] 최대 스택에서 같은 무기를 먹으려 하면 픽업이 소비되지 않는다.
- [ ] 다른 무기로 교체하면 기존 강화 스택과 픽업 공격력 보너스가 0으로 초기화된다.
- [ ] 호스트가 강화했을 때와 게스트가 강화했을 때 서버 피해 결과가 동일하다.

확인 로그:

```text
[WeaponPickup] Same weapon upgraded: ... Stack=1/3 ...
[WeaponPickup] Same weapon upgraded: ... Stack=2/3 ...
[WeaponPickup] Same weapon upgraded: ... Stack=3/3 ...
```

## 7. 샷건 총구와 다중 투사체

- [ ] 샷건 탄환이 손이나 캐릭터 중심이 아니라 `Muzzle` 소켓에서 시작한다.
- [ ] 비조준과 ADS 상태 모두 총구 위치가 자연스럽다.
- [ ] 데이터의 `ProjectileCount`만큼 투사체가 한 번에 생성된다.
- [ ] 투사체가 생성 직후 서로 충돌해 대량으로 풀에 반환되지 않는다.
- [ ] 샷건 탄환이 지정된 `SpreadAngleDegrees` 범위로 퍼진다.
- [ ] 한 번 발사할 때 탄약은 투사체 수와 무관하게 1만 감소한다.
- [ ] 벽 앞에서 발사하면 탄환이 벽을 관통해 뒤의 플레이어에게 피해를 주지 않는다.
- [ ] 발사한 캐릭터 자신과 충돌하지 않는다.
- [ ] 수명·충돌·사거리 종료 후 모든 투사체가 풀로 반환된다.
- [ ] 호스트와 게스트 양쪽 샷건 발사가 동일하게 동작한다.

밸런스 시작 권장값:

```text
FirePattern = Spread
ProjectileCount = 6~8
SpreadAngleDegrees = 약 10
ProjectileDamageMultiplier = 약 0.2
```

`ProjectileCount=20`, 투사체당 피해 약 31 상태는 전탄 명중 시 약 620 피해이므로 정상 작동 이후 그대로 유지하면 과도하다.

## 8. 회귀 검증

- [ ] 권총과 소총의 단발 발사가 기존처럼 동작한다.
- [ ] 권총·소총·샷건 모두 조준점 방향으로 발사한다.
- [ ] 탄약 차감, 재장전, HUD 갱신이 일치한다.
- [ ] 쉴드 픽업은 쉴드가 최대가 아닐 때만 소비된다.
- [ ] 쉴드가 있으면 HP보다 쉴드가 먼저 감소한다.
- [ ] 사망·리스폰 후 무기, 탄약, 쉴드, HUD가 정상 복구된다.
- [ ] 팀 점수와 적군 HP Bar가 무기 교체 이후에도 정상 갱신된다.

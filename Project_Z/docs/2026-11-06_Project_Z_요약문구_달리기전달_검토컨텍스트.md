### 핵심 정리

> Unreal의 서버·클라이언트 처리 구조와 네트워크 기능 활용 방식을 이해하고, 이를 적용한 멀티플레이 기능 설계·구현 경험 확보.

기존 Unity 경험을 Unreal의 클래스·RPC·상태 복제에 적용한 것으로 설명한다. 새로운 전송 계층이나 독립 서버를 개발한 경험으로 설명하지 않는다.

## 5. 현재 코드

2026-11-06 읽기 전용으로 확인한 내용이다. 아래는 설명용 코드 발췌이며 수정 제안이 아니다.

```cpp
// 헤더
UFUNCTION(Server, Reliable)
void ServerSetRunning(bool bRunning);

float WalkSpeed = 300.0f;
float SprintSpeed = 600.0f;
bool bIsRunning = false; // 현재 Replicated 지정 없음

// cpp
void AZCharacter_FPS::StartRun()
{
    if (!IsLocallyControlled() || IsPlayerDead())
    {
        return;
    }

    ApplyRunningState(true);
    if (!HasAuthority())
    {
        ServerSetRunning(true);
    }
}

void AZCharacter_FPS::StopRun()
{
    if (!IsLocallyControlled())
    {
        return;
    }

    ApplyRunningState(false);
    if (!HasAuthority())
    {
        ServerSetRunning(false);
    }
}

void AZCharacter_FPS::ServerSetRunning_Implementation(bool bRunning)
{
    if (IsPlayerDead())
    {
        bRunning = false;
    }

    ApplyRunningState(bRunning);
}

void AZCharacter_FPS::ApplyRunningState(bool bRunning)
{
    bIsRunning = bRunning;
    if (UCharacterMovementComponent* MovementComponent = GetCharacterMovement())
    {
        MovementComponent->MaxWalkSpeed = bIsRunning ? SprintSpeed : WalkSpeed;
    }
}
```

WalkSpeed·SprintSpeed는 실제 헤더에서 EditDefaultsOnly 속성이므로 Blueprint 저장값이 다를 수 있다. 여기서는 기본값과 핵심 코드를 발췌했다.

## 6. 사용자의 의문과 이전 답변

1. 사용자: ‘게스트 달리기는 각각 상태값을 전달한 것 아닌가?’
2. 에이전트: 게스트가 달리기 여부를 서버 RPC로 전달하고 로컬·서버에서 각각 적용한다고 설명. bIsRunning을 모든 클라이언트에 복제한 것은 아니며 이동 반영은 CharacterMovement 경로라고 설명.
3. 사용자: 그렇다면 표의 ‘게스트 달리기는 로컬과 서버에 각각 속도 적용’은 틀린 설명 아닌가?
4. 에이전트: 적용 결과 설명은 맞지만 RPC로 달리기 여부를 전달하는 과정이 빠져 있다고 답하고 현재 표의 문장으로 수정.
5. 사용자: 다른 에이전트에게 물을 수 있도록 컨텍스트 작성 요청.

이전 에이전트 설명의 옳고 그름도 검토 대상이다. 사용자가 어느 부분을 다른 의미로 이해했는지 먼저 확인하고, 단순히 같은 문장을 반복하지 않는다.

## 7. 검토할 때 구분할 사항

- 전달 인자 bRunning과 각 인스턴스의 멤버 bIsRunning.
- Server RPC 호출과 UPROPERTY 변수 복제.
- 최대 이동 속도 MaxWalkSpeed와 현재 실제 이동 속도.
- 소유 게스트의 로컬 캐릭터와 서버의 해당 캐릭터, 다른 클라이언트가 보는 캐릭터.
- 달리기 입력 처리와 Animation Blueprint의 애니메이션 전환. 이번 코드 확인에서는 ABP 그래프를 열지 않았으므로 실제 전환 조건을 단정하지 않음.
- 로컬이 먼저 true를 적용하더라도 서버는 사망 상태면 false를 적용할 수 있음. 양쪽에 같은 값이 무조건 보장된다고 표현하지 않음.

# Project_Z FPS 멀티플레이 전체 개발 보고서

- 작성일: 2026-10-26
- 프로젝트: Project_Z
- 개발 환경: Unreal Engine 5.7, C++, Blueprint, Listen Server
- 목표 인원: 최대 6인
- 게임 구성: Team A / Team B 기반 소규모 FPS
- 현재 단계: 핵심 기능 구현 완료 단계, 최종 네트워크 검증 및 오류 수정 진행 중

## 1. 보고서 목적

기존 Project_Z의 맵, 캐릭터, 무기 및 전투 데이터를 활용해 Listen Server 기반 FPS 멀티플레이 기능을 구축한 과정과 현재 상태를 정리한다.

본 문서는 다음 내용을 포함한다.

- 개발 목표와 확정된 설계 원칙
- 클래스별 책임과 네트워크 권한 구조
- FPS 이동·조준·전투·사망·리스폰 구현
- 팀 선택·스폰·HUD·마커·점수 구현
- Projectile 및 오브젝트 풀 처리
- 쉴드 아이템과 쉴드 시각화
- 지금까지의 검증 결과와 미검증 항목
- 알려진 문제와 최종 작업 우선순위

코드가 존재한다는 사실과 실제 멀티플레이 검증이 완료됐다는 사실을 구분해 기록한다.

## 2. 최초 목표와 개발 범위

직무 과제 계획서의 최종 목표는 기존 Project_Z를 다음 조건의 FPS 멀티플레이 샘플로 확장하는 것이다.

- Listen Server 기반 접속
- 최대 6인 플레이
- 2팀 구성
- FPS 이동, 시점 및 점프
- 서버 권한 발사, 충돌 및 피해 처리
- 탄약, 재장전 및 HUD 동기화
- 사망과 리스폰
- 서버 팀 배정, 팀별 스폰 및 팀 정보 표시
- 접속·퇴장 상태 관리
- 패킷 지연·손실 환경 검증
- 구현 의도와 오류 수정 과정 문서화

### 원안 대비 구현 방식 변경

- 계획서에 적힌 서버 Hitscan 판정을 사용하지 않고 서버 권한 Projectile 충돌 방식으로 변경했다.
- 서버가 팀을 배정하는 초기 구상에서 접속자가 Team A 또는 Team B를 직접 선택하고 서버가 승인하는 방식으로 변경했다.

### 원안 외 추가 기능

- LeftShift 달리기와 네트워크 속도 동기화
- ADS 카메라·무기 보간과 Aim Offset
- Team A/B 상단 HUD, 캐릭터 머리 위 팀 마커 및 벽 뒤 가림
- 팀 처치 점수
- 쉴드 데이터, 쉴드 아이템, 쉴드 HUD, 자동 생성 지점 및 캐릭터 보호막

### 범위 변경이 아닌 유지·보류 항목

- 최대 6인과 패킷 지연·손실 검증은 원래 필수 범위이며 삭제되지 않았다. 현재 미검증 상태다.
- 외부 Go 서버 연동은 후속 프로젝트 아이디어이며 이번 직무 과제 원안에 포함되지 않았다.
- TPS 전환은 추진하지 않고 원안대로 FPS에 집중한다.
- 무기 위치, 손 정렬, 카메라 감각 등의 연출은 기능 검증 이후로 우선순위만 조정했다.

## 4. 네트워크 설계 원칙

### 4.1 서버 권한

다음 결과는 서버에서만 확정한다.

- 팀 선택 승인
- 캐릭터 생성과 리스폰 위치
- Projectile 생성
- Projectile 충돌과 피해
- HP와 쉴드 차감
- 탄약 소비와 재장전 완료
- 사망 판정
- 처치 점수
- 쉴드 아이템 생성과 획득

클라이언트는 입력을 서버 RPC로 요청하고, 서버가 변경한 상태는 Replication 또는 RepNotify를 통해 전달받는다.

### 4.2 상태 저장 위치

- 경기 전체 점수와 팀 관계: GameState
- 리스폰 후에도 유지되어야 하는 플레이어 팀: PlayerState
- 현재 생명, 탄약, 무기 및 쉴드 상태: Character
- 서버 전용 게임 규칙과 타이머: GameMode
- 로컬 UI와 입력 요청: PlayerController

팀 정보를 Pawn에만 저장하지 않은 이유는 사망 후 Pawn이 제거되고 새 Pawn으로 교체되기 때문이다.

## 5. FPS 캐릭터 및 입력

### 5.1 기본 이동

구현 항목:

- WASD 이동
- 마우스 시점 회전
- 점프 시작·종료
- FPS 카메라 연결
- 로컬 소유 캐릭터 입력 분리
- CharacterMovement 기반 네트워크 이동

초기 2인 PIE 환경에서 호스트와 게스트의 개별 이동, 회전 및 점프를 확인했다.

### 5.2 달리기

LeftShift 달리기는 다음 값으로 구성한다.

| 상태 | 속도 |
|---|---:|
| 걷기 | 300 cm/s |
| 달리기 | 600 cm/s |

2026-10-26 게스트 달리기 실패와 이동 끊김을 수정했다.

- 로컬 캐릭터만 `MaxWalkSpeed`를 변경하던 문제 제거
- `ServerSetRunning` Reliable RPC 추가
- 클라이언트와 서버에 같은 달리기 상태 적용
- Shift 해제를 `Completed`, `Canceled`에서 모두 처리
- `Move()`가 매 프레임 속도를 덮어쓰던 코드 제거

전체 빌드는 성공했으며 호스트·게스트 PIE 재검증이 남아 있다.

세부 기록: [게스트 달리기 및 이동 끊김 버그 수정 보고서](2026-10-26_Project_Z_게스트_달리기_이동끊김_개발보고서.md)

### 5.3 조준과 Aim Offset

구현 항목:

- ADS 입력
- FPS 카메라 위치·회전 및 FOV 보간
- 1인칭 무기 위치·회전·크기 보정값
- `AO_Rifle2` 기반 상하 Aim Offset 연결
- 로컬 플레이어와 원격 플레이어의 Aim Pitch 적용

Aim Offset Alpha를 1.0으로 사용할 때 1인칭 팔과 무기가 시야에서 사라지는 문제가 있어 강도와 본 포즈의 조정이 필요했다. 기능 연결은 완료했지만 무기·팔·총구의 최종 연출 수치는 확정하지 않았다.

## 6. 무기와 전투

### 6.1 무기 데이터 적용

공통 무기 처리 로직을 `AZCharacterBaseMulti`로 이관했다.

- 무기 Data Asset 적용
- 탄약 초기화
- 재장전 상태와 애니메이션
- Skeletal/Static 무기 Mesh 지원
- 무기 Socket, 위치, 회전 및 Scale 적용
- Projectile 클래스, 속도, 피해량 및 수량 적용

FPS 전용 카메라·조준 표현은 `AZCharacter_FPS`에 유지했다.

### 6.2 발사 처리

전투 흐름은 다음과 같다.

```text
로컬 발사 입력
  → ServerRequestFire RPC
  → 서버 발사 가능 여부·탄약·쿨다운 확인
  → 서버가 Object Pool에서 Projectile 획득
  → 서버 Projectile 이동 및 충돌
  → 서버 피해 적용
  → HP/쉴드 상태 복제
```

Hitscan 판정은 사용하지 않는다.

### 6.3 Projectile와 충돌

구현 및 확인 항목:

- 서버 권한 Projectile 생성
- 캐릭터 및 월드 충돌
- 장애물 뒤 플레이어 피격 차단
- 연속 발사 중 중복 피해 방어
- 수명 종료 후 오브젝트 풀 반환
- 충돌 후 풀 반환
- Projectile 재사용 시 런타임 상태 초기화
- 발사자와 자기 자신 충돌 예외 처리

벽 관통 문제는 월드와 Projectile의 Collision Response를 조정한 뒤 사용자 실행 기준 정상 동작을 확인했다.

### 6.4 탄약과 재장전

구현 항목:

- 서버 탄약 차감
- 탄약 부족 시 발사 제한
- 재장전 요청의 서버 처리
- 재장전 타이머
- 재장전 완료 시 탄약 갱신
- 사망 또는 상태 변경 시 재장전 취소
- 탄약 HUD 갱신

호스트와 게스트의 탄약 값 및 HUD 값 일치는 사용자 테스트 기준 확인됐다.

## 7. 피해, HP, 사망 및 리스폰

### 7.1 피해 처리

피해는 서버의 `ReceivePlayerDamage()`에서 처리한다.

주요 순서:

1. 서버 권한과 사망 상태 확인
2. 공격자와 피해자의 팀 관계 확인
3. 아군 피해 차단
4. 피해 배율 적용
5. 쉴드 우선 차감
6. 남은 피해를 HP에 적용
7. HP가 0이면 사망 처리
8. GameMode에 처치 등록

### 7.2 월드 HP Bar

- 피격 플레이어 캐릭터 위에 HP Bar 표시
- HP 감소 상태를 RepNotify/GAS Attribute 변경으로 갱신
- 호스트가 게스트를 공격하거나 게스트가 호스트를 공격하는 양방향 표시 수정
- 월드 공간 Widget의 표시 시간 관리

한때 HP Bar가 간헐적으로 보이지 않는 현상이 보고됐으나 이후 재현되지 않았다. 원인이 확정되지 않았으므로 완전히 해소된 결함으로 판정하지 않는다.

### 7.3 사망과 리스폰

구현 항목:

- 서버 HP 0 판정
- 사망 상태 복제
- 이동과 입력 제한
- 사망 애니메이션
- 재장전 취소
- 서버 지연 리스폰
- 새 Pawn 생성 및 Possess
- PlayerState의 팀 유지
- 팀별 PlayerStart 사용

기본 사망·리스폰 흐름은 2인 환경에서 확인했으며, 팀 선택·점수·쉴드 추가 이후의 전체 회귀 검증은 다시 수행해야 한다.

## 8. 팀 시스템

### 8.1 팀 선택

접속 시 자동 배정 대신 사용자가 Team A 또는 Team B를 선택한다.

```text
팀 선택 UI
  → PlayerController 서버 요청
  → GameMode 유효성 검사 및 승인
  → PlayerState에 팀 저장·복제
  → 팀별 스폰 요청
```

구현 및 확인 항목:

- 접속 후 팀 선택 UI 표시
- Team A / Team B 선택
- 서버 승인
- PlayerState 팀 저장
- 선택 전 Pawn 생성 대기
- 스폰 실패 시 재시도 경로
- 팀 선택 후 HUD 전환

### 8.2 팀별 스폰

Team A와 Team B PlayerStart를 사용한다. 같은 팀의 여러 플레이어가 한 지점에서 겹치지 않도록 PlayerStart 주변의 빈 공간을 탐색한다.

- 캐릭터 Capsule 크기 기준 후보 계산
- 바닥 Line Trace
- Walkable Floor 검사
- Capsule Overlap 검사
- 유효한 첫 위치 사용
- 공간이 없으면 대기열에 보관하고 타이머로 재시도
- 탐색 영역과 실패 원인을 로그로 출력

다중 플레이어가 같은 팀 스폰 주변에 생성되는 기본 동작은 사용자 테스트 기준 정상으로 보고됐다.

### 8.3 팀 HUD와 마커

구현 항목:

- `WBP_FPS_HUD` 상단 중앙에 `WBP_TeamStatus` 배치
- `TEAM A 0 : 0 TEAM B` 표시
- 캐릭터 머리 위 Team A / Team B 마커
- 로컬 팀 관계에 따른 표시 갱신
- 벽 뒤 마커 숨김
- 시야가 다시 확보되면 마커 재표시

HUD와 마커 및 벽 뒤 가림은 2인 PIE에서 확인했다.

### 8.4 팀 점수

구현 규칙:

- 적 팀 플레이어 처치: 공격자 팀 점수 +1
- 같은 팀 처치: 점수 없음
- 자살 또는 공격자 불명: 점수 없음
- GameState 점수를 전체 클라이언트에 복제

코드와 UI 연결은 완료했지만 실제 처치 후 호스트·게스트 양쪽에서 같은 점수가 증가하는지에 대한 최종 PIE 검증 기록은 없다.

승리 점수, 라운드 종료 및 점수 초기화 정책은 아직 범위가 확정되지 않았다.

## 9. 접속·퇴장 및 재접속

구현 항목:

- PostLogin 진입 처리
- 팀 미선택 상태의 스폰 차단
- Logout 후 PlayerArray와 팀 인원 갱신 로그
- 최초 스폰 실패 재시도
- Listen Server 직접 접속

게스트 재접속은 `open 127.0.0.1:17777`을 사용했을 때 정상 동작이 보고됐다. 그러나 PIE 세션 구성과 포트에 의존하는 수동 확인이므로 반복 가능한 공식 검증으로 종료하지 않았다.

다음 항목은 여전히 필요하다.

- 호스트 유지 상태에서 게스트 반복 접속·종료
- 재접속 후 팀 재선택
- 기존 호스트의 팀·점수 유지
- 최대 6인 접속
- 7번째 접속 거절 정책 구현 및 검증

## 10. 쉴드 시스템

### 10.1 쉴드 데이터와 피해

`AZCharacterBaseMulti`에 다음 상태를 추가했다.

| 항목 | 값 |
|---|---:|
| 기본 쉴드 | 0 |
| 최대 쉴드 | 100 |
| 아이템 1개 회복량 | 50 |

쉴드가 존재하면 쉴드를 먼저 차감하고 초과 피해만 HP로 전달한다. 쉴드 값은 서버에서 변경하고 RepNotify로 클라이언트와 HUD를 갱신한다.

### 10.2 쉴드 아이템

- `BP_ShieldPickup` 생성
- 서버 Overlap 획득
- 최대 쉴드 상태에서는 미소비
- 회복 성공 시 서버에서 제거
- 반투명 하늘색 구체 외형
- `ShieldSpawn` 태그 TargetPoint 사용
- 현재 맵에 9개 생성 지점 배치
- 게임 시작 약 1초 후 최대 9개 일괄 생성
- 이후 10초마다 비어 있는 지점을 일괄 보충

### 10.3 쉴드 HUD와 보호막 표현

- 기존 Stamina ProgressBar 디자인을 쉴드 게이지로 재사용
- 실제 데이터는 Stamina가 아닌 별도 `CurrentShield`, `MaxShield` 사용
- 캐릭터 주변에 반투명 하늘색 Fresnel 보호막 표시
- 쉴드가 0보다 클 때만 표시
- 쉴드 소진 또는 사망 시 숨김
- 본인 1인칭 화면에서는 `Owner No See`
- 다른 플레이어에게는 복제 상태를 기준으로 표시

쉴드 코드, Blueprint 및 머티리얼 에셋은 생성됐지만 호스트·게스트 통합 PIE 검증은 아직 완료되지 않았다.

## 17. 결론

Project_Z는 기존 TPS 중심 코드에서 공통 전투 기능을 멀티플레이 캐릭터 기반으로 정리하고, FPS 카메라·입력·조준·Projectile 전투·사망·리스폰·팀 선택·팀별 스폰·팀 HUD·마커·점수 및 쉴드까지 연결한 상태다.

2인 Listen Server 환경의 핵심 전투와 팀 표시 기능은 상당 부분 동작이 확인됐다. 현재 남은 핵심 과제는 새로운 기능을 더 추가하는 것이 아니라 다음 네 가지를 실제 실행으로 증명하는 것이다.

1. 최신 변경을 포함한 2인 전체 회귀 테스트
2. 팀 점수와 쉴드 통합 검증
3. 최대 6인 접속·전투 검증
4. 패킷 지연·손실 환경 검증

따라서 현재 단계에서 기능 확장은 중단하고 검증, 오류 수정 및 최종 문서화에 집중하는 것이 일정과 과제 목표에 가장 타당하다.

## 18. 2026-10-26 추가 구현: 무기 픽업·공용 스폰·샷건

### 18.1 FPS 무기 진행 구조

- FPS 캐릭터는 최초 스폰과 리스폰 시 항상 권총으로 시작한다.
- 필드에서 권총·소총·샷건을 습득할 수 있다.
- 다른 무기를 습득하면 현재 무기를 즉시 교체하고 새 무기의 기본 탄약을 적용한다.
- TPS의 기존 무기 허용 정책은 변경하지 않았다.
- 별도 인벤토리, 무기 슬롯 전환과 기존 무기 드롭은 이번 범위에 포함하지 않았다.

### 18.2 동일 무기 강화

- 현재 무기와 정확히 같은 Weapon Data를 다시 습득하면 기본 공격력의 10%를 추가한다.
- 최대 3스택, 총 30%까지 증가한다.
- 다른 무기로 교체하면 동일 무기 강화 스택과 전용 공격력 보너스를 초기화한다.
- 최대 스택에서는 같은 무기 픽업을 소비하지 않아 다른 플레이어가 사용할 수 있게 했다.
- 강화 판정과 최종 Projectile 피해 계산은 서버에서 처리한다.

### 18.3 TargetPoint 공용 픽업 슬롯

- `ShieldSpawn` 태그가 지정된 TargetPoint를 쉴드 전용 지점이 아닌 공용 픽업 슬롯으로 전환했다.
- 게임 시작 시 모든 태그 지점에 픽업을 일괄 생성한다.
- 생성 후보는 쉴드·권총·소총·샷건이다.
- 완전 독립 랜덤으로 한 종류가 과도하게 몰리는 문제를 막기 위해 4종 셔플 백을 사용한다.
- 픽업 제거 시 해당 지점에 독립 타이머를 설정하고 10초 후 재생성한다.
- 재생성 지점에 Pawn이 있거나 공간을 사용할 수 없으면 이후 다시 시도한다.
- Blueprint에 저장된 과거 `MaxShieldPickupCount` 값이 C++ 기본값을 덮어써 1개만 생성되던 의존성을 제거했다.

### 18.4 샷건 발사 수정

- `SKM_Shotgun` 총열 끝에 `Muzzle` 소켓을 추가하고 `DA_Weapon_Shotgun.MuzzleSocketName`과 연결했다.
- 로그상 샷건은 설정된 다중 Projectile을 획득했지만 동일 위치에서 생성된 Projectile끼리 충돌해 대부분 즉시 풀로 반환되고 있었다.
- 같은 샷에서 생성된 Projectile끼리 이동 충돌과 Overlap을 무시하도록 수정했다.
- 발사체가 발사한 캐릭터와 이동 충돌하지 않도록 처리했다.
- 풀 재사용 시 과거 이동 충돌 무시 목록을 초기화한다.
- 사용자 단일 실행 확인에서 샷건 다중 발사는 정상화됐다고 보고됐다.

# Project_Z 쉴드 기능 및 2026-10-25 작업 계획

## 1. 목적

2026-10-25 작업은 기존 멀티플레이 기본 기능의 회귀 테스트와 버그 수정을 우선하고, 아래 두 기능을 추가한다.

1. 월드에서 획득할 수 있는 쉴드 아이템
2. 쉴드 수치와 HUD 쉴드 게이지

이번 작업은 기능 검증이 목적이다. 쉴드 파괴 이펙트, 사운드, 재질 변화, 세부 밸런싱 등의 연출은 범위에서 제외한다.

## 2. 현재 코드 기준 판단

- 멀티플레이 캐릭터 피해 진입점은 `AZCharacterBaseMulti::ReceivePlayerDamage()`이다.
- `ReceiveEnemyDamage()`도 `ReceivePlayerDamage()`를 호출하므로 플레이어 및 적 공격의 쉴드 처리를 한 곳에 모을 수 있다.
- 현재 HUD의 세 번째 막대는 `ProgressBar_Stamina`이며 `GetCurrentStaminaValue()`와 `GetMaxStaminaValue()`를 표시한다.
- 기존 `Stamina` 변수까지 쉴드로 재해석하면 이후 달리기/스태미나 기능과 충돌하고 이름과 실제 의미가 달라진다.
- 따라서 **HUD 막대 디자인은 재사용하지만 쉴드 데이터는 별도 변수로 구현**한다.

## 3. 확정 구현 규칙

### 3.1 쉴드 데이터

`AZCharacterBaseMulti`에 서버 권한형 쉴드 상태를 둔다.

- `CurrentShield`: 현재 쉴드
- `MaxShield`: 최대 쉴드
- 두 값은 클라이언트 HUD 갱신을 위해 복제한다.
- 초기값 제안: `CurrentShield = 0`, `MaxShield = 100`
- 리스폰 시 새 캐릭터의 쉴드는 `0`으로 시작한다.
- 쉴드 자동 재생은 이번 범위에 포함하지 않는다.

### 3.2 피해 처리 순서

피해 처리는 서버에서만 수행한다.

1. 사망 여부와 피해값 검증
2. 아군 공격 차단
3. 기존 `RuntimeDamageTakenMultiplier` 적용
4. `CurrentShield`에서 먼저 피해 흡수
5. 쉴드보다 큰 잔여 피해만 HP에 적용
6. HP가 0일 때 기존 사망·점수·리스폰 흐름 실행

계산 규칙:

```text
ShieldDamage = Min(CurrentShield, FinalDamage)
CurrentShield -= ShieldDamage
HPDamage = FinalDamage - ShieldDamage
HP -= HPDamage
```

예시:

- Shield 40, Damage 25 -> Shield 15, HP 피해 0
- Shield 20, Damage 35 -> Shield 0, HP 피해 15
- Shield 0, Damage 35 -> HP 피해 35

`OnDamageReceived()`에는 실제 HP 피해가 아니라 피격 전체 반응이 필요할 수 있다. 구현 시 HP 바 표시 목적과 피격 반응 목적을 분리해서, 쉴드가 전부 흡수해도 피격 사실은 정상 표시되도록 확인한다.

### 3.3 쉴드 아이템

최소 기능용 `AZShieldPickupActor`를 추가한다.

- 서버에서만 획득 성공을 확정한다.
- 기본 회복량 제안: `ShieldAmount = 50`
- 결과는 `Min(CurrentShield + ShieldAmount, MaxShield)`로 제한한다.
- 쉴드가 이미 최대면 아이템을 소비하지 않는다.
- 두 플레이어가 동시에 접근해도 한 명만 획득해야 한다.
- 성공한 경우에만 아이템을 제거한다.
- 빠른 기능 완성을 위해 1차 구현은 자동 Overlap 획득 방식으로 한다.
- `[F] PICKUP` 상호작용 방식은 필요할 경우 후속 작업으로 분리한다.

### 3.4 HUD

기존 `WBP_StateHUD`의 `ProgressBar_Stamina` 배치와 외형을 쉴드 게이지로 재사용한다.

- C++ 표시 데이터는 `CurrentShield / MaxShield`로 변경한다.
- 함수는 `UpdateShield(CurrentShield, MaxShield)`로 의미를 명확히 한다.
- 블루프린트 위젯 변수명 `ProgressBar_Stamina`는 내일 기능 구현 중 유지해도 된다. 이름 변경은 BindWidget 연결 파손 위험이 있으므로 기능 검증 후 수행한다.
- 쉴드 0이면 0%, 최대면 100%로 표시한다.
- 호스트와 게스트는 각각 자신의 쉴드만 자신의 화면에 표시한다.

### 남은 보호막 시각화 검증

- 에디터 종료 후 `Development Editor / Win64` 전체 빌드 및 재실행
- 호스트와 게스트가 상대방의 보호막을 모두 볼 수 있는지 확인
- 자신의 1인칭 화면이 보호막 내부 색으로 덮이지 않는지 확인
- 쉴드 획득 시 표시되고, 쉴드가 0이 되는 타격에서 즉시 사라지는지 확인
- 구체 크기가 캐릭터 전신을 감싸면서 벽 너머 판독을 과도하게 방해하지 않는지 확인

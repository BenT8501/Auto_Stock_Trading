# Project_Z 네트워크 재접속 이슈 — 미해결·보류

기록일: 2026-10-23

## 현재 상태

- 사용자가 오늘도 네트워크 재접속이 되지 않는다고 보고했다.
- 사용자 요청에 따라 원인 추적과 수정은 중단하고 이후 작업으로 보류한다.
- 이번 작업은 기록만 수행했다. 소스·에셋·접속 설정을 변경하지 않았고 빌드·실행 테스트 및 커밋·푸시를 수행하지 않았다.
- 로컬 HEAD는 `9196cc7`(재 접속 버그 수정)이지만, 커밋 제목과 별개로 사용자 최신 실행 보고를 기준으로 **미해결**로 유지한다. 이번 기록에서는 해당 수정 코드의 원인 분석을 수행하지 않았다.

## 재현 환경과 증상

- 같은 PC에서 Listen Server와 게스트 창을 사용하는 PIE 테스트.
- 최초 접속에서는 서로의 캐릭터가 보였으나 게스트 연결 해제 후 재접속 과정에서 상대 캐릭터가 보이지 않는다고 보고했다.
- 호스트/게스트 양쪽에서 서로 보이지 않는 증상이 있었다.
- 콘솔 open 명령 및 PIE 재시작·설정 확인을 안내했지만 정상 재접속 복구를 확인하지 못했다.
- 실제로 입력한 최종 접속 명령, 호스트의 실제 리슨 포트, 접속 시도 직후의 실패 로그는 대화에서 확보하지 못했다. 원인을 IP나 포트 설정 오류로 확정하지 않는다.

## 확보한 로그

```text
[Reconnect] NetMode=2, World=MultiMap, Players=2, MyPawn=BP_ZCharacter_FPS_C_0
[Reconnect] Character=BP_ZCharacter_FPS_C_0, Local=1, Hidden=0, Location=X=-1050.000 Y=3400.000 Z=90.150
[Reconnect] NetMode=3, World=MultiMap, Players=2, MyPawn=BP_ZCharacter_FPS_C_1
[Reconnect] Character=BP_ZCharacter_FPS_C_0, Local=0, Hidden=0, Location=X=-1050.000 Y=3400.000 Z=90.150
[Reconnect] Character=BP_ZCharacter_FPS_C_1, Local=1, Hidden=0, Location=X=440.000 Y=-3770.000 Z=90.100
[Reconnect] NetMode=0, World=MultiMap, Players=1, MyPawn=BP_ZCharacter_FPS_C_0
[Reconnect] Character=BP_ZCharacter_FPS_C_0, Local=1, Hidden=0, Location=X=440.000 Y=-3770.000 Z=90.150
```

로그에서 확인된 상태와 확정된 원인을 구분한다.

- 최초 로그에는 Listen Server(NetMode=2)와 Client(NetMode=3)가 있다. 클라이언트 월드에 상대 캐릭터도 존재했다.
- 마지막 기록은 Standalone(NetMode=0), Players=1이다. 해당 시점은 연결된 클라이언트 월드가 아니다.
- 이 결과만으로 접속 실패 원인, PIE 실행 설정 문제, 연결 종료 후 전환 경로 중 어느 것이 원인인지 확정할 수 없다.
- 로그는 EnterGamePlayUI에서 출력하도록 안내했으므로 각 월드의 입장 시점 스냅샷이다. 첫 호스트 로그에 캐릭터가 하나라는 사실만으로 서버 복제 실패를 판정하지 않는다.

## 보류 범위와 재개 시 확인 순서

1. 사용자 최신 코드와 당시 PIE 실행 설정을 먼저 확인한다. 현재 상태를 임의로 초기화하지 않는다.
2. 호스트가 계속 실행 중인지, 실제 리슨 주소·포트가 무엇인지 확인한다. 포트를 추정한 open 명령을 반복하지 않는다.
3. 게스트가 실행한 접속 명령과 그 직후 LogNet, Browse, TravelFailure, NetworkFailure 로그를 확보한다.
4. 재접속 시 호스트의 PostLogin 호출 여부와 게스트 NetMode=3 여부를 확인한다.
5. 같은 서버 연결이 확인된 다음 PlayerArray, Pawn 생성·소유·복제, 팀 선택 초기 상태 및 원격 메시 표시를 확인한다.
6. 필요할 경우 별도 프로세스 실행으로 PIE 재접속 조건을 분리하되, 실행 구성을 먼저 설명하고 기존 설정을 보존한다.

완료 기준은 호스트를 유지한 채 게스트가 새로 연결되어 팀을 선택하고, 양쪽에서 서로의 캐릭터·팀 정보가 보이며 기존 호스트의 점수·팀이 유지되는 것이다. 현재는 이 기준을 충족했다고 기록하지 않는다.

참고: 최초 스폰 실패 후 입장 재시도는 별도 기능이다. 네트워크 연결 해제 후 재접속 이슈와 섞어서 완료 처리하지 않는다.

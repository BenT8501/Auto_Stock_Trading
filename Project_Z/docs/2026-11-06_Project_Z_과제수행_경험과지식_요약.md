# Project_Z 과제 수행 — 쌓은 경험과 지식 요약

## 핵심 정리

**Unreal의 서버·클라이언트 처리 구조와 네트워크 기능 활용 방식을 이해하고, 이를 적용한 멀티플레이 기능 설계·구현 경험 확보.**

기존 Unity 멀티플레이 경험을 바탕으로 Unreal의 클래스 구조·RPC·상태 복제를 실제 기능에 적용. 새로운 네트워크 기술을 개발한 성과보다, Unreal에서 기능을 연결하고 동작 차이를 확인·수정한 경험에 중점.

## 구체적으로 익힌 내용과 적용 경험

| 익힌 내용 | 직접 적용한 사례 |
|---|---|
| **서버·클라이언트에서 기능이 실행되는 방식** | 발사·재장전·아이템 습득 요청을 서버에서 검사·처리. 달리기는 로컬에 즉시 적용하고, 달리기 여부를 서버 RPC로 전달하여 서버에서도 최대 이동 속도 변경 |
| **서버의 변경값이 각 화면에 반영되는 과정** | 탄약·쉴드·팀·점수 등을 복제하고, 조회·변경 알림으로 HUD·무기 표현 갱신. C++ 서버의 직접 갱신과 클라이언트 OnRep 처리 구분 |
| **클래스별 데이터 보관과 객체 수명** | 팀은 PlayerState에 저장해 일반 리스폰 후 유지. HP·탄약은 캐릭터에 보관하고 새 Pawn 생성 시 초기화. 점수·시간은 GameState로 공유 |
| **데이터 반영 시점이 다른 상황의 처리** | 재경기 시 초기화 번호·팀 미선택·Pawn 제거를 확인하고 서버에 준비 응답. 준비 응답 대기 중 다음 경기 시작 보류 |
| **호스트·게스트의 동작 차이를 확인하는 방법** | 입력·서버 처리·값 변경·복제·화면 갱신을 나누어 확인. 게스트 달리기와 전투·HUD 불일치 원인 조사·수정 |

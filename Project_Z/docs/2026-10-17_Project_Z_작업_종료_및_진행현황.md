## 2. 확정된 개발 원칙

- 현재 과제는 FPS 멀티플레이 기능 완성을 우선한다.
- 실제 전투 판정은 Hitscan이 아니라 서버 권한 Projectile 충돌 방식이다.
- 무기 위치, 손 정렬, ADS 카메라 감각, Aim Offset 강도 등 연출 조정은 핵심 기능 완료 후 진행한다.
- 팀 정보는 리스폰 때 교체되는 Pawn이 아니라 PlayerState에 저장한다.
- GameMode는 서버 권한 결정, GameState는 전체 플레이어 상태 조회, PlayerState는 개별 플레이어의 지속 상태를 담당한다.

## 4. 완료로 판정하지 않은 항목

### 팀 자동 배정 런타임 검증

팀 코드는 구현·빌드됐지만 PIE 네트워크 실행 검증 전이다. 다음 로그를 확인하기 전까지 기능 완료로 처리하지 않는다.

```text
[Team] Assigned Player=... Team=EZPlayerTeam::TeamA ...
[Team] Assigned Player=... Team=EZPlayerTeam::TeamB ...
[Team] Replicated Player=... Previous=... New=... NetMode=...
```

확인 조건:

1. Listen Server 2인 실행 시 A/B 각각 한 명 배정
2. 각 클라이언트에서 두 PlayerState의 팀 값 복제 확인
3. 3인 실행 시 A/B/A 배정 확인
4. 사망·리스폰 후 기존 PlayerState의 팀 유지 확인

### HP Bar 간헐 미표시

- 한때 HP Bar가 간헐적으로 표시되지 않는 현상이 보고됐다.
- 이후 반복 테스트에서는 재현되지 않았다.
- 원인과 수정 여부가 확정되지 않았으므로 완료가 아니라 관찰 이슈로 유지한다.

재현될 경우 확인할 로그:

```text
[HP_BAR] Replicated HP decreased
[HP_BAR] Cannot show
[HP_BAR] visible = 1
```

특히 리스폰 직후 첫 피격에서만 발생하는지 구분해야 한다.

## 6. 다음 작업 순서

### 1순위: 팀 자동 배정·복제 검증

1. Unreal Editor를 재실행한다.
2. `BP_Project_Z_GameMode_MultiPlay`의 부모가 `Project_Z_MultiGameMode`인지 확인한다.
3. Game State Class가 `Project_Z_MultiGameState`인지 확인한다.
4. Player State Class가 `Project_Z_MultiPlayerState`인지 확인한다.
5. Listen Server 2인으로 실행하고 `[Team] Assigned`, `[Team] Replicated` 로그를 확인한다.
6. 한 명을 사망·리스폰시킨 뒤 팀 값이 유지되는지 확인한다.

`[Team] Team assignment failed`가 출력되면 GameMode Blueprint가 기존 GameState 또는 PlayerState 클래스를 덮어썼을 가능성을 우선 확인한다.

### 2순위 이후

1. 최소 팀 UI 및 진영 식별 표시
2. 팀 태그 기반 PlayerStart 선택
3. 팀별 최초 스폰 및 리스폰 검증
4. 접속·퇴장 상태 정리
5. 최대 6인 제한 및 초과 접속 처리
6. 6인 접속·전투 및 패킷 손실 환경 검증

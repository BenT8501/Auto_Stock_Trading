# Project_Z 팀 선택 검증 현황 및 다음 일정

작성일: 2026-10-21

대상: BenT8501/WorkSpace, Project/Project_Z

코드 확인 기준: `c60a20f` — 팀선택 까지 완료

## 1. 기록 범위와 판정 원칙

사용자가 직접 구현하고 에이전트는 가이드·검토·기록을 담당한다. 이번 변경은 문서만 추가·갱신하며 소스와 에셋은 수정하지 않는다. 빌드 및 PIE도 실행하지 않았다.

이 문서는 [10/20 진행 기록](2026-10-20_Project_Z_팀선택_UI_진행현황.md) 이후 결과를 정리한다. 이전 문서의 RPC 미구현 및 수정 대기 상태는 아래 최신 상태로 갱신해서 읽는다. 커밋 제목이 완료라고 되어 있어도 구현 확인과 실행 검증은 구분한다.

사용자 결정: 재시도 성공 테스트는 지금은 보류하고 다음 기능으로 진행한다. 따라서 재시도 기능 전체를 검증 완료로 표시하지 않는다.

## 2. 유지하는 설계

- C++에서 UI 동작과 상태를 처리하고 WBP는 배치·스타일을 담당한다.
- A/B 클릭은 Widget의 임시 SelectedTeam만 변경한다.
- 입장 버튼을 눌러 Controller → 서버 GameMode에 선택을 요청한다.
- 서버 승인 후에는 접속 중 팀 변경을 허용하지 않는다.
- 확정 팀은 PlayerState에 저장하며 사망·리스폰 후에도 유지한다.
- 최초 입장 재시도는 이미 승인된 팀으로만 수행한다. 사망 후 지연 리스폰과 구분한다.
- 전투 HUD의 팀 표시는 임시 SelectedTeam이 아닌 소유 PlayerState의 확정 팀을 사용한다.

“B를 선택해도 A가 된다”는 보고에 대해 UI/서버 로그는 모두 TeamB였다. 따라서 해당 사례는 선택값 저장 오류로 판정하지 않는다. 시작점이 막혔을 때 이전 시작점으로 스폰되는 경로와 맵 배치·태그를 구분해서 확인해야 한다.

## 5. 보류한 재시도 테스트

환경: Listen Server와 클라이언트 창. 사용자는 벽을 복사하여 시작점과 겹치게 배치했다.

확인된 흐름:

```text
B 선택 → 서버에 B 저장 → 해당 시작점 충돌 검사 실패
 → 스폰 실패 결과 → 재시도 버튼 표시
 → 재시도 → 시작점을 찾지 못하면 다시 Failed
```

Failed 로그 자체는 크래시를 뜻하지 않는다. 장애물이 계속 존재하면 실패가 반복되는 것은 정상적인 검색 결과일 수 있다.

보류 항목은 “같은 접속에서 서버의 장애물을 제거한 뒤 재시도로 B팀 위치에 스폰”하는 성공 경로다. PIE F8 편집 및 임시 지연 제거 테스트는 안내했지만 성공 확인을 받지 않았다. 이후 회귀 테스트 목록에 유지한다.

## 6. 코드 검토에서 발견한 잔여 수정 사항

이번에는 기록만 했으며 사용자 소스를 수정하지 않았다.

### 6.1 서버 재시도 함수의 실패 분기에서 return 누락

`Private/Controllers/Project_Z_MultiPlayerController.cpp`의 ServerRetryInitialSpawn_Implementation에서 GameMode가 유효하지 않으면 결과 RPC를 보내지만 return하지 않는다. 이후 World->GetTimeSeconds 또는 GameMode->RestartPlayer로 진행할 수 있다.

필요 수정: `if (!IsValid(GameMode))` 분기에서 결과 전달 직후 return. 재시도 성공 테스트를 보류하더라도 이 오류 경로는 별도 수정 항목이다.

### 6.2 최초 선택 서버 함수의 GameMode 유효성 검사 누락

같은 파일의 ServerRequestTeamSelection_Implementation은 World는 검사하지만 GetAuthGameMode의 반환값을 검사하지 않고 TrySelectPlayerTeam을 호출한다.

필요 수정: GameMode 유효성 검사 후 실패 결과를 전달하고 return. 정상 구성에서 항상 존재한다는 가정으로 오류 경로를 생략하지 않는다.

### 6.3 스폰 실패 시 테스트용 액터 삭제 코드가 남음

`Private/GameModes/Project_Z_MultiGameMode.cpp`의 RestartPlayer에는 시작점 검색 실패 시 월드의 AStaticMeshActor를 순회하여 Actor Tag가 SpawnBlocker인 액터를 Destroy하는 코드가 있다.

이는 테스트 보조 동작이며 정식 스폰 실패 정책으로 확정한 기능이 아니다. 그대로 두면 스폰 실패가 맵의 물체 삭제로 이어진다. 테스트 재개 여부와 관계없이 일반 게임 흐름에서는 제거하거나 명시적인 테스트 경로로 분리할 정리 항목으로 남긴다. 이번 문서화에서 삭제하지 않았다.

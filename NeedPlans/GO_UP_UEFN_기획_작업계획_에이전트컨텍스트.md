## 1. 게임 개요

**GO ~! UP!!!!**은 최대 9명이 각자 건설하며 목표 높이를 향해 올라가는 개인전 경주 게임이다. 시작 상자에서 건설 자원과 무기를 얻고, 상승 중 다른 플레이어나 건축물을 공격해 아이템을 확보한다. 아래에서 올라오는 위험한 물이 정체를 막으며, 목표 높이에 먼저 도달한 플레이어가 승리한다.

핵심 흐름:

```text
참가·시작 위치 배정 → 시작 상자 획득 → 건설·상승
  → 상대 또는 건축물 공격 → 자원·아이템 획득 → 추가 건설
  → 일정 높이에서 새 보물 상자 등장 → 상승 반복
  → 60초 주기의 물 상승 압박 → 목표 높이 최초 도달자 승리
```

전투는 상승을 돕거나 상대를 방해하는 수단이다. 처치 수 우승이나 최후 생존자 우승으로 임의 변경하지 않는다.

| 항목 | 요구 내용 |
| :-- | :-- |
| 이름 | GO ~! UP!!!! |
| 장르 | 건설·상승 경주와 PvP가 결합된 미니게임 |
| 인원·관계 | 최대 9명, Free For All 개인전 |
| 이동 핵심 | Fortnite의 기본 빌드 시스템으로 위로 올라감 |
| 시작 보급 | 상자에서 빌드용 아이템과 무기 획득 |
| 중간 보급 | 일정 위치까지 올라가면 새로운 보물 상자 생성 |
| 전투·획득 | 무기로 상대 플레이어나 건물을 파괴해 아이템 획득 |
| 처치 보상 | 죽인 상대가 가지고 있던 모든 아이템을 획득할 수 있음 |
| 위험 요소 | 바닥에서 물 같은 위험 요소가 60초마다 올라오며, 빠지면 HP 감소 |
| 승리 | 목표 높이에 먼저 도달한 플레이어 |

## 3. 확정 전 질문과 제안

아래 제안은 사용자 확정 사항이 아니다. 답변 전까지 임시 실험값으로만 사용한다.

| 결정할 내용 | 초안 제안 | 확인 이유 |
| :-- | :-- | :-- |
| 맵 배치 | 9개의 시작 구역을 가진 분리된 상승 경로 | 각자 건설하면서 상대를 견제하는 재미를 먼저 확인 |
| 물 상승 방식 | 경기 시작 후 매 60초마다 일정 높이만큼 상승하고 다음 상승 전까지 유지 | ‘60초마다 상승’과 UI의 의미를 일치시킴. 상승 애니메이션 시간은 별도 |
| 위험 판정 | 잠수 여부보다 위험 수면 아래 신체 기준점 진입으로 지속 피해 | 수영으로 위험을 무기한 회피할 수 없게 설계하되 실제 물 접촉 판정과 비교 필요 |
| 사망 | 초기 테스트는 1회 생명·관전 방식 제안 | 부활 위치·보급·물 상승에 의한 무한 사망 문제를 줄임. 사용자 결정 필요 |
| 전원 사망·미도달 | 무승부 또는 별도의 제한 시간 결과 | 최초 도달 승리만으로 종료되지 않는 상황 처리 |
| 마지막 1명 | 자동 승리 여부 미정 | 원래 목표 높이 우승 규칙과 다르므로 임의로 자동 승리시키지 않음 |
| 처치 아이템 획득 | 자동 이전인지 현장 드롭 후 습득인지 확인 | 멀리 떨어진 경로에서 처치하면 직접 습득하기 어려움 |
| 중간 상자 | 플레이어별 높이 도달 보상 우선 검토 | 공용 1회 보상은 선두 독주를 키울 수 있음 |
| 건물 파괴 보상 | 배치된 자원 건물에 한정하는 안부터 검토 | 자기가 만든 구조물을 반복 설치·파괴해 자원을 늘리는 문제 방지 |
| 낙하 피해·건축 붕괴 | 켜짐·꺼짐과 허용 범위 미정 | 바닥 하나 파괴로 경기가 과도하게 짧아지는지 확인 |
| 진행 중 참가 | 다음 경기 대기 또는 관전 제안 | 이미 물이 오른 경기의 바닥에서 시작하는 문제 방지 |
| 재경기·퇴장 | 결과 확인 후 다음 라운드와 퇴장 동작 필요 | 경기 종료 이후의 사용자 흐름까지 완결 |

물 상승량, 피해량·피해 간격, 시작 자원, 상자 높이, 목표 높이, 경기 길이는 아직 정하지 않았다. 임의의 값을 확정 기획처럼 전달하지 않는다.

## 4. 맵 논의안

### A안: 3×3 분리 구역

9개 시작 지점을 3×3으로 배치하고 각 구역 위로 건설한다. 제작과 거리 비교가 쉽다. 중앙 플레이어가 여러 방향에서 공격받고, 모서리 플레이어는 견제받는 방향이 적다는 차이가 있다.

### B안: 원형 배치

시작 구역 9개를 원주에 배치한다. 이웃 구역까지 거리를 맞추기 쉽지만 반대편은 멀어지고 중앙을 향해 다리를 놓는 전략이 생긴다.

### C안: 구역 분리 없이 공용 공간

공격·습득·이동의 상호작용은 많지만 초반 근접 교전이 건설 경주를 압도할 수 있다. ‘처음에는 점프·아이템으로 건널 수 없음’ 조건을 만족시키는 시작 구역 설계가 필요하다.

**첫 검증 제안:** 9개를 완성하기 전에 시작 구역 2개와 작은 목표 높이로 건설·사격·자원 소모를 비교한다. 재미와 거리 조건이 성립하면 9개 배치로 늘린다. 2명 검증은 최종 최대 인원을 줄인다는 뜻이 아니다.

### 거리와 높이 산정

- 거리 기준은 시작점 중심 사이가 아니라 실제로 건널 수 있는 가장 가까운 가장자리 사이 거리다.
- 시작 시 허용할 이동 수단을 먼저 고른 뒤 질주 점프·맨틀·슬라이딩·공중 사용을 포함한 최대 이동 거리를 측정한다.
- 구역 간격은 그 최대 거리보다 여유 있게 크고, 채택한 무기가 실제로 유효한 피해를 줄 수 있는 거리보다 작아야 한다.
- 이후 건설한 다리로 다른 구역에 침입하는 것을 허용할지는 별도 결정이다. 처음부터 영구 차단벽을 확정하지 않는다.
- 골인 판정은 단순 Z 좌표만 볼지, 목표 높이의 지정 골인 영역 진입을 볼지 정한다. 임시로 골인 영역을 제안한다.
- Unreal 좌표 단위와 건축 타일 단위를 섞지 않는다. 목표 높이는 허용 건축 높이·공간 범위에서 실제 배치해 검증한다.

### 자원과 물의 균형

`필요 자원 ≈ 구간 상승에 필요한 구조물 수 × 구조물당 비용 + 방어·우회 여유분`

시작 보급으로 첫 중간 보급까지 도달할 수 있어야 한다. 추가 처치가 없어도 상승 가능한 기본 자원을 검토한다. 건물 파괴 보상이 필수라면 파괴 가능한 대상과 접근 동선을 제공한다. 물이 한번 오르는 높이와 보급 높이를 함께 조정해, 초보가 첫 상자에도 못 가거나 모두 물을 무시하는 상황을 피한다.

## 5. UEFN 구현 방향과 선행 검증

일반 Unreal C++ 프로젝트의 GameMode·PlayerController를 그대로 만드는 계획이 아니다. Fortnite 기본 시스템과 장치, 필요한 Verse 로직을 조합한다. 아래 장치와 함수는 후보이며 완성된 연결·코드가 있다는 뜻이 아니다.

| 기능 | 활용 방향 | 추가 구현·검증 |
| :-- | :-- | :-- |
| 개인전·9명 | Island Settings, Player Spawner | 개인전 설정과 실제 시작 위치 배정, 중복 스폰 확인 |
| 건설·무기·탄약 | Fortnite 기본 건설·전투·인벤토리 | 건설 허용, 자원 제한, 건축 피해, 선택 무기·아이템 조합 검증 |
| 시작 상자 | 실제 상자 또는 상자 외형+상호작용+Item Granter 후보 | 각자 1회인지 공용인지, 실제 보급 내용과 수량, 중복 개봉 방지 |
| 중간 보물 상자 | 높이 구역 감지 후 미리 배치한 상자 활성화 또는 생성 기능 검증 | 단순 아이템 생성과 ‘새 상자 등장’을 구분. 개인·공용·도달 순서 처리 |
| 물 상승 | Water device의 수위 제어 후보 | 60초 주기와 단계별 수위 정지, 경기 시작·종료·재설정 시 수위 동기화 |
| 물 피해 | Damage Volume 또는 Verse의 주기적 위험 판정 후보 | 물의 시각적 높이와 피해 범위 일치, 경계 진입·이탈·사망 처리 |
| 처치 후 전리품 | 기본 탈락 아이템·자원 Drop 설정부터 검증 | ‘공격자에게 모든 소지품 자동 이전’과 같은 기능은 아님. 정확한 수량·종류·탄약·슬롯 제한을 별도 검증 |
| 건물 파괴 보상 | 자원 수확 설정 또는 별도로 정의한 파괴 가능 보급 대상 | 임의 건축물 파괴 시 임의 아이템 보상이 자동 지급된다고 가정하지 않음 |
| 목표 도달·승자 | 골인 구역과 End Game 장치 연계 후보 | 생존·경기 단계 확인, 최초 승자 1회 확정, 동시 진입 처리 |
| UI | 기본 자원·탄약·인벤토리 HUD 우선 활용, 시간은 별도 표시 | 무기 총개수 등 추가 표시 항목의 조회 방법 확인. 미지원 값은 가짜 수량으로 표시하지 않음 |

Epic 문서상 Island Settings는 건설·탈락·HUD 관련 설정을 제공한다. 프로젝트에서는 선택한 규칙과 다른 장치의 덮어쓰기 여부를 확인해야 한다. [Island Settings](https://dev.epicgames.com/documentation/fortnite/island-settings-in-unreal-editor-for-fortnite)

Water 장치는 수위를 제어할 수 있지만 수영도 가능한 물이다. 따라서 물을 배치하는 것과 위험 지역으로 만드는 것은 따로 검증한다. [Water Devices](https://dev.epicgames.com/documentation/en-us/fortnite/using-water-devices-in-fortnite-creative), [Damage Volume Devices](https://dev.epicgames.com/documentation/fortnite/using-damage-volume-devices-in-fortnite-creative)

Verse `water_device` 문서에는 `BeginVerticalFilling`, `BeginVerticalEmptying`과 물 진입·이탈 이벤트가 있다. 원하는 높이마다 정확히 멈추는 구현은 설치 버전 API와 장치 동작을 검증한 뒤 결정한다. 임의의 수위 설정 함수를 만들어 설명하지 않는다. [water_device API](https://dev.epicgames.com/documentation/fortnite/verse-api/fortnitedotcom/devices/water_device)

탈락 시 아이템·자원을 드롭하는 설정과 공격자에게 고정 자원을 주는 설정이 있다. 이것만으로 피해자의 모든 실제 인벤토리를 원격 이전할 수 있다고 결론내리지 않는다. 이 요구는 우선순위가 높은 기술 검증 항목이다. [Team Settings & Inventory](https://dev.epicgames.com/documentation/en-us/fortnite/using-team-settings-and-inventory-devices-in-fortnite-creative)

Item Spawner는 아이템 공급에 쓸 수 있지만 보물 상자의 생성·개봉·개인별 지급까지 모두 대신한다고 보지 않는다. [Item Spawner](https://dev.epicgames.com/documentation/en-us/fortnite/using-item-spawner-devices-in-fortnite-creative)

## 6. 구현 순서와 완료 기준

날짜나 기간은 아직 산정하지 않는다. 도구 경험과 선행 검증 결과를 보고 잡는다. 각 단계 통과 후 다음 단계로 진행한다.

| 순서 | 주요 작업 | 하는 이유·완료 기준 |
| :-- | :-- | :-- |
| 0 | UEFN 버전·프로젝트 위치·실행 환경 확인, 미정 규칙 협의 | 다른 플랫폼 코드나 기존 Project_Z를 섞지 않고 작업 범위 확정 |
| 1 | 작은 테스트 맵, 시작 지점 2개, 시작 상자, 기본 건설과 무기 연결 | 두 플레이어가 보급받고 건설하며 서로 공격 가능. 시작 점프·아이템으로는 건너지 못함 |
| 2 | 전리품·파괴 보상·수위 단계 제어·추가 HUD 조회 기술 실험 | 중요한 요구가 실제 장치/API로 가능한지 먼저 결정. 자동 이전 불가 시 대안을 사용자와 협의 |
| 3 | 낮은 목표 구간과 골인 판정, 시작·진행·종료 상태 연결 | 1등 도달 시 한 번만 경기 종료. 도중 탈락이 임의 우승으로 바뀌지 않음 |
| 4 | 60초 카운트다운·물 상승·지속 피해 | 모든 참가자에게 같은 다음 상승 시점 표시, 수면 밖에서는 피해 없음 |
| 5 | 중간 높이 보물 상자와 자원 순환 | 도달 시 실제 상자가 등장·활성화되고 정해진 횟수만 보급 |
| 6 | 9명 맵 확장·시작 위치·사선·보급량 조정 | 9명에게 유효 위치 배정, 특정 배치만 과도하게 유리하지 않은지 검증 |

## 7. 경기 상태와 주요 데이터 초안

```text
대기 → 시작 카운트다운 → 진행 → 종료 → 결과 → 다음 라운드
                          ├ 물 상승 반복
                          ├ 높이 보상 개방
                          └ 최초 유효 골인 → 승자 확정
```

- 경기 공통: 경기 단계, 경기 식별값, 목표 높이/골인 영역, 다음 물 상승 시각, 현재 물 단계·수위, 승자, 참가자 목록.
- 플레이어별: 시작 구역, 생존/관전 상태, 상자·높이 보상 수령 기록.
- 기본 무기·탄약·자원 값은 Fortnite 시스템이 관리하는 값을 우선 사용한다. 실제 인벤토리와 따로 노는 복제 수량표를 만들지 않는다.
- 물 시간은 경기 시작을 기준으로 관리한다. 플레이어마다 접속 시점부터 따로 60초를 세지 않는다.
- 종료 후에는 물 피해·보상·골인 중복 처리를 막고 재경기 때 구독·타이머·개봉 기록·드롭·건축물 초기화를 검증한다.

## 9. 다른 에이전트에게 전달할 사항

1. 사용자는 UEFN으로 새 미니게임을 만들고자 한다. 기존 Unreal Project_Z 보고서 작업과 별개다.
2. 이 문서는 계획이며 구현 완료 기록이 아니다. 실제 프로젝트가 있는지와 경로부터 확인한다.
3. 우선 맵·사망·전리품·상자 규칙을 협의하고, 첫 작업은 작은 2인 건설·전투 실험으로 제안한다.
4. 사용자에게 한 단계씩 안내하고, 요청받지 않은 프로젝트 코드나 에디터 자산을 임의 수정하지 않는다. 문서 생성은 이번에 요청받았다.
5. UEFN의 실제 장치/API를 확인한다. 일반 Unreal C++ 설계나 Roblox의 RemoteEvent 구조를 그대로 제시하지 않는다.
6. ‘죽인 상대의 모든 아이템 획득’ 요구를 단순 고정 처치 보상으로 바꾸지 않는다. 자동 이전과 드롭 습득 차이를 먼저 설명한다.
7. 맵 거리·목표 높이·물 상승량은 실측 전 확정 숫자를 만들지 않는다. 장치 후보도 사용자 승인된 최종 설계로 취급하지 않는다.
8. 위 체크리스트를 기준으로 완료·진행·미검증 항목을 나눠 기록한다. 구현만으로 테스트 완료라고 쓰지 않는다.

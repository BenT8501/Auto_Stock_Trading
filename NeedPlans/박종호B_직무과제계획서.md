# 직무 과제 계획서

## 1. 업무명

Unreal Engine 기반 기존 Project_Z의 소규모 FPS 멀티플레이 기능 설계 및 구현

## 2. 배경 및 목표

### 배경

Unity 멀티플레이 개발 경험을 기반으로 Unreal Engine 프로젝트 파견 업무를 수행하기 위해서는 엔진 주요 기능의 동작 방식과 클래스별 역할을 이해하고, 담당 기능의 처리 흐름과 설계 의도를 팀원에게 명확히 설명할 수 있어야 합니다. 이에 기존 Project_Z에 멀티플레이 기능을 추가하여 Unreal의 게임플레이 구조와 네트워크 처리에 대한 이해를 높이고, 구현 내용을 근거로 기술적 의사소통 역량을 강화하고자 합니다.

### 목표

기존 Project_Z의 맵과 게임플레이 기능을 활용하여 최대 6명이 참여하는 2팀 FPS 샘플 프로젝트를 구현합니다. Listen Server 기반으로 접속, 이동, 발사, 피격, 사망, 리스폰 등의 핵심 플레이 흐름과 팀별 스폰 및 점수 처리를 구현합니다.

주요 클래스의 역할과 서버·클라이언트의 책임을 구분하고, 상태의 저장 위치와 수명을 설계합니다. 다중 클라이언트 및 지연·패킷 손실 환경에서 동작을 검증하고, 설계 의도와 발생한 오류의 원인 및 수정 내용을 설명할 수 있는 수준의 역량 확보를 목표로 합니다.

## 3. 기대효과

- 클래스별 역할과 데이터 흐름을 파악하여 기능의 구현 위치와 변경 영향 범위를 검토하고, 기능 수정 및 추가 업무에 대한 대응 능력을 강화합니다.
- 설계도와 실제 코드의 실행 흐름을 근거로 구현 의도와 동작을 설명하여 팀원과의 기술적 의사소통을 개선합니다.
- 멀티플레이 오류의 재현, 원인 분석, 수정 및 재검증 경험을 확보하여 문제 해결 능력을 향상합니다.

## 4. 업무일정

**개발 일정: 4주 / 20근무일 — 설계·구현·통합 검증 및 기술 문서 정리 포함, 시연 준비 제외**

기존 Project_Z의 맵과 구현된 게임플레이 기능을 재사용하는 것을 전제로 합니다. 멀티플레이 기초 학습과 설계 기록은 기능 구현 과정에 포함합니다. 1주차에 재사용 가능 여부를 확인하고, 미구현 부가 기능의 신규 제작은 제외하여 접속·전투·팀 배정·리스폰을 우선 확보합니다.

| 주차 | 주요 작업 | 기간 | 완료 기준 및 산출물 |
|---|---|---|---|
| 1주차 | 기존 구조 분석, 클래스 역할·상태 배치 설계, 접속·이동·충돌 및 서버 발사 요청 기반 구성 | 5일 | 2인 접속·이동 확인, 서버 발사 요청 전달, 클래스 역할도·상태 배치표 |
| 2주차 | 서버 발사 검증·명중·피해 처리, 체력·탄약·HUD 및 기존 전투 연출 동기화 | 5일 | 호스트와 클라이언트의 피해·탄약 결과 일치, 전투 처리 흐름도 |
| 3주차 | 재장전·사망·리스폰, 팀 배정·팀별 스폰·킬/데스·팀 점수, 접속·퇴장 처리 | 5일 | 최대 6명 팀전 기능 구현, 상태 유지·초기화 규칙 확인 |
| 4주차 | 다른 PC 및 6인 통합 검증, 지연·패킷 손실·예외 상황 테스트, 오류 수정·재검증 | 5일 | 검증 완료 빌드, 테스트 결과·오류 분석 기록·설계 문서 |
| **합계** | **개발 및 검증** | **20일** | **시연 준비 별도** |

### 적용 범위 및 일정 관리 기준

- 기존 맵을 활용한 최대 6명, 2팀, Listen Server 방식의 멀티플레이를 대상으로 합니다.
- 호스트 실행 및 클라이언트 접속 경로를 확보합니다. 별도 방 목록·로비 UI, 계정, 랭킹, 자동 매칭, 전용 서버 운영은 제외합니다.
- 외부 인터넷 접속이 필요한 경우 1주차에 접속 방식과 검증 환경을 확정하고 일정 내 구현 가능 여부를 확인합니다.
- 방어구·반동·애니메이션은 기존 구현의 멀티플레이 연동을 대상으로 합니다.
- 기능별 확인은 해당 구현 작업에 포함하며, 4주차에는 다중 클라이언트·네트워크 조건·예외 상황을 조합한 통합 검증을 수행합니다.
- 설계 근거와 오류 기록은 개발 중 작성하고 4주차에 검토·보완합니다. 문서 재작성 작업을 별도로 중복 배정하지 않습니다.
- 핵심 기능 구현은 3주차까지 완료하고, 4주차는 통합 검증·오류 수정·재검증에 사용합니다.
- 시연 시나리오, 발표 자료, 영상 제작, 시연 환경 설치 및 리허설은 20근무일에서 제외하고 별도로 일정을 산정합니다.

### 주요 검증 완료 기준

- 최대 6명이 접속하여 팀을 배정받고 진영별 위치에서 생성됩니다.
- 서버가 발사·피해·탄약을 처리하며 호스트와 클라이언트에 일치하는 상태가 반영됩니다.
- 사망이 중복 집계되지 않고, 리스폰 시 팀·점수는 유지되며 전투 상태는 정해진 규칙에 따라 초기화됩니다.
- 접속·퇴장과 지연·패킷 손실 조건에서 핵심 흐름을 확인하고, 발견 오류의 수정·재검증 결과와 잔여 제약을 기록합니다.
- 클래스별 역할, 상태 저장 위치·수명, 주요 RPC 및 Replication 흐름을 문서와 코드로 설명할 수 있습니다.

### 개발 완료 산출물

- 기존 Project_Z에 멀티플레이 기능을 추가한 소스 코드 및 검증 완료 실행 빌드
- 클래스 역할도, 상태 저장 위치·수명 표, 주요 기능 실행 흐름도
- 다중 클라이언트 및 지연·패킷 손실 테스트 결과
- 주요 오류의 원인 분석·수정·재검증 기록 및 잔여 제약 사항
- 호스트 및 클라이언트 실행·접속 안내

시연 시나리오, 발표 자료, 예비 영상 및 리허설은 별도 시연 준비 일정의 산출물로 관리합니다.

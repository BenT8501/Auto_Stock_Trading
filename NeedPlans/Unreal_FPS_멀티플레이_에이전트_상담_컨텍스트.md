# Unreal FPS 멀티플레이 과제 상담 컨텍스트

> 갱신일: 2026-09-23. 상담 합의에 따른 제안안이며 상사 승인 전이다.

## 업무명

Unreal Engine 기반 소규모 FPS 멀티플레이 프로토타입 설계 및 구현

## 배경 및 목표

파견 업무 준비를 위한 독립적인 신규 과제다. Unity 멀티플레이 경험은 있지만 Unreal 네트워크 개발은 처음이다. 이전 평가에서 Unreal 기능의 정확한 이해와 구현 의도·실행 흐름을 명확하게 설명하는 능력의 부족을 지적받았다. 이전 과제의 구현 경험을 숙련의 근거로 단정하거나 기존 프로젝트 확장으로 진행하지 않는다.

GAS를 제외하고 Unreal 네트워크 프레임워크, 클래스별 책임, 상태 수명과 실행 흐름 이해에 집중한다. 기능을 많이 만드는 것보다 실제 코드와 검증 결과로 설계 이유를 설명하는 것을 목표로 한다. 엔진이 제공하는 기능을 활용하며 별도의 범용 프레임워크 개발은 목표로 하지 않는다.

과제에 전념하는 8주·주 5일, 총 40일 기준이다. 시작일과 공휴일은 실제 회사 일정에 맞춘다.

## 기대효과

- 기능 수정 시 구현 위치와 관련 상태·영향 범위를 판단한다.
- 서버·클라이언트의 역할, 변경 권한, 전달 대상과 상태 수명을 설명한다.
- 오류의 재현 조건·로그·원인·수정 결과로 팀원과 구체적으로 소통한다.
- 실행 결과물과 설계·검증 기록으로 이해도와 설계 능력을 확인받는다.

## 합의된 범위

- Listen Server 기반 최대 6명·2팀, 캐릭터 1종·테스트 맵 1개
- 1인칭 카메라·로컬 팔·원격 전신 Mesh, 이동·조준
- Hitscan 총기 1종, 서버 권한 발사·피격·데미지
- 체력·탄약·재장전, 수직·수평 반동과 연사 누적·한도·회복, 총·팔 반동 연출
- 방어구 2종: 고정 피해 차감량만 다름. 인벤토리·내구도·등급·부위별 장비 없음
- 방어구는 개발용 선택값 또는 테스트 입력으로 적용하는 계획안이며 별도 장착 UI는 만들지 않음
- 피해 계산안: 최종 피해 = Max(0, 기본 피해 - 방어구 차감량). 수치는 구현 전 결정
- 사망 애니메이션, Kill/Death·팀 점수, 팀별 리스폰
- Collision Channel·Profile, Physics Asset 피격 영역, Line Trace 검사
- 기본 접속·퇴장 처리, 지연·패킷 손실 테스트, 검증용 최소 HUD
- GameMode·GameState·PlayerController·PlayerState·Character·Weapon·필요한 Component의 책임 설계

충돌·피격 검사에 물리·충돌 시스템을 활용한다. 동적 물리 시뮬레이션과 Ragdoll은 제외한다. 반동은 조준 변화와 연출로 구현하며 물리 시뮬레이션으로 설명하지 않는다.

## 제외 및 후속 학습

- GAS 전체: ASC·Ability·Effect·AttributeSet 및 GAS 예측·보정
- 회복 아이템·추가 스킬·부위별 데미지 배율·무기 파츠
- Ragdoll·물리 Projectile·폭발 충격량·이동식 물리 오브젝트
- Physical Material별 반응 확장, 정식 점수판·Kill Feed·경기 종료 UI
- 재접속 상태 복구·Dedicated Server·매치메이킹·외부 백엔드
- 자체 전투 예측·보정·Lag Compensation·전문 치팅 방지

서버 기본 요청 검증은 포함한다. 엔진의 기본 이동 네트워크 처리는 활용한다. GAS를 제외한 시간은 새 기능보다 설계·검증·설명 보완에 사용한다.

## 8주 주간·일간 일정

매일 핵심 개념·설계 이유·검증 결과·설명이 어려운 부분을 짧게 기록한다. 매주 발표는 전제하지 않는다. 2주·4주에 자체 진도를 점검하며 상사 점검은 가능하면 4주 차, 최종 보고는 8주 차로 제안한다.

| 2일 | Listen Server 2인 접속. 호스트·클라이언트 구분 로그 | 코드의 실행 위치를 확인하기 위해 |

|---|---|---|

## 일정 운영 및 결과물

- 2주 차에는 2인 조작과 상태 전달 설명 수준을, 4주 차에는 최소 전투 완성을 점검한다.
- 핵심 구현이 지연되면 팀전 확장 전에 원인을 해결하고 후속 작업을 재배치한다.
- GAS 제외로 확보한 여유는 오류 수정·이해도 보완에 사용하며 새 기능을 자동 추가하지 않는다.
- 방어구 선택 방식, 리스폰 시 방어구 유지 여부, 아군 공격 등 세부 규칙은 구현 전 기록한다.

# 다음 과제 제안서

## 과제명

**Unreal Engine Replication을 활용한 1인칭 6인 팀전 FPS 멀티플레이 전투 구현**

## 1. 과제 선정 배경

현재 회사 프로젝트가 FPS PvP 장르를 중심으로 구성되어 있으므로, 다음 과제는 실제 업무와 연결되는 Unreal Engine 멀티플레이 기초 기술을 학습하고 검증하는 방향으로 진행한다.

이번 과제는 별도의 백엔드 서버를 개발하거나 대규모 온라인 서비스를 구축하는 것이 목적이 아니다. Unreal Engine이 제공하는 네트워크 프레임워크를 이용해 서버와 클라이언트의 역할, Replication, RPC 및 멀티플레이 게임 상태 관리의 기본 구조를 이해하는 것을 목표로 한다.

서버 개발 경험이 없는 상태에서 시작하는 만큼, 최대 6명의 플레이어가 하나의 테스트 맵에 접속하여 2개 팀으로 나뉘어 이동하고 전투한 뒤 사망과 팀 점수 반영, 리스폰까지 수행하는 작은 규모의 플레이 가능한 결과물을 완성한다.

## 2. 과제 목표

다음과 같은 최소 FPS PvP 플레이 흐름을 구현한다.

```text
서버 실행
→ 클라이언트 최대 6명 접속
→ 2개 팀 배정
→ 플레이어 이동 및 회전 동기화
→ 무기 발사
→ 서버 피격 판정 및 데미지 적용
→ 체력 동기화
→ 플레이어 사망
→ 처치 및 팀 점수 반영
→ 일정 시간 후 리스폰
```

핵심 학습 목표는 다음과 같다.

- Unreal Engine의 서버·클라이언트 구조 이해
- 1인칭 시점의 이동·조준·사격 구현
- Authority와 Ownership의 차이 이해
- Replication과 RPC의 사용 목적 구분
- GameMode, GameState 및 PlayerState의 역할 구분
- 서버 기준의 데미지·사망·점수 처리 구현
- 여러 플레이어 환경에서 발생하는 동기화 문제 확인 및 수정

## 3. 구현 범위

### 3.1 멀티플레이 접속 및 캐릭터

- 에디터에서 서버 1개와 클라이언트 최대 6개 실행
- 최대 6명의 플레이어 생성, 접속 및 2개 팀 배정 확인
- 팀별 Spawn Point에서 플레이어 생성
- 플레이어 이동과 회전 동기화
- 접속 및 퇴장 로그 확인
- 각 플레이어와 팀을 구분할 수 있는 이름 또는 색상 표시
- 로컬 플레이어는 1인칭 카메라와 1인칭 전용 팔 Mesh 사용
- 다른 플레이어에게는 전신 Mesh와 장착 장비 표시
- 카메라 회전, 캐릭터 회전 및 무기 조준 방향 동기화

### 3.2 무기 및 전투

- Hitscan 방식의 기본 총기 1종 구현
- 발사 입력과 발사 가능 여부 처리
- 발사 요청을 Server RPC로 전달
- 서버에서 Line Trace 및 피격 대상 판정
- 서버에서 데미지 적용
- 플레이어 체력 Replication
- 부위별 피격 판정과 데미지 배율 적용
- 탄약 소모 및 재장전 상태 동기화
- 발사 이펙트와 사운드를 다른 플레이어에게 표시

### 3.3 물리 엔진 및 충돌 처리

- 캐릭터 Capsule Component와 Skeletal Mesh의 Collision Profile 구성
- 무기 Line Trace용 Collision Channel 분리
- Skeletal Mesh Physics Asset을 활용한 신체 피격 영역 구성
- Physical Material을 활용한 표면별 피격·충돌 반응 구분
- 서버 권한의 충돌 판정과 물리 상태 검증
- 사망 시 제한적인 Ragdoll 전환 및 리스폰 시 물리 상태 초기화

이번 과제에서는 물리 엔진을 모든 게임 오브젝트에 적용하지 않고, 캐릭터 충돌·피격 판정·사망 표현에 한정한다. 물리 기반 Projectile, 폭발 충격량, 이동식 물리 오브젝트 및 복잡한 차량 물리는 후속 과제로 분리한다.

### 3.4 부위별 데미지

HitResult의 Bone Name 또는 별도 Hit Box를 기준으로 피격 부위를 판정한다. 최종 판정과 데미지 계산은 서버에서 수행한다.

| 피격 부위 | 초기 데미지 배율 | 방어 장비 |
|---|---:|---|
| 머리 | 2.0 | 방탄 헬멧 |
| 상체 | 1.0 | 방탄 조끼 |
| 팔·손 | 0.75 | 총기 파지 장비, 장갑 |
| 다리 | 0.7 | 무릎보호대, 군화 |

배율은 초기 테스트 값이며 DataTable 또는 DataAsset에서 조정할 수 있게 구성한다. 방어구는 해당 부위의 최종 피해를 감소시키되, 서버가 장착 상태와 피해 감소율을 검증한다.

### 3.5 회복 아이템

- 테스트 맵에 회복 아이템을 배치하고 플레이어가 획득하여 사용할 수 있게 구성한다.
- 회복 아이템의 획득 가능 여부와 사용 요청을 서버에서 검증한다.
- 사용 시 일정량의 체력을 회복하며, 최대 체력을 초과하지 않도록 서버에서 제한한다.
- 아이템 획득, 사용, 소모 수량 및 재사용 대기시간을 Replication한다.
- 피격, 사망, 이동 등 사용 취소 조건을 정의하고 서버에서 적용한다.
- 회복량, 사용 시간, 재사용 대기시간 및 최대 보유 수량은 DataAsset으로 관리한다.

클라이언트는 아이템 사용 입력과 즉각적인 시각·청각 피드백을 담당하고, 서버는 사용 조건과 최종 회복량을 판정한다.

### 3.6 플레이어 방어구 파츠 (후속 단계)

플레이어는 다음 여섯 개의 방어구 슬롯을 가진다.

| 슬롯 | 기본 효과 방향 |
|---|---|
| 방탄 조끼 | 상체 피해 감소 |
| 무릎보호대 | 다리 피해 감소 또는 앉기·슬라이딩 안정성 향상 |
| 총기 파지 장비 | 팔 피해 보정 또는 조준 안정성 향상 |
| 장갑 | 무기 교체·재장전 속도 향상 |
| 방탄 헬멧 | 머리 피해 감소 |
| 군화 | 이동 소음 감소 또는 이동 성능 보정 |

각 파츠는 장착 슬롯, 능력치, 피해 감소율 및 외형 정보를 DataAsset으로 관리한다. 파츠 장착 결과와 다른 플레이어에게 보여야 하는 외형은 서버 기준으로 동기화한다.

### 3.7 무기 파츠 (후속 단계)

기본 총기에 다음 여섯 종류의 파츠 슬롯을 제공한다.

| 파츠 | 기본 효과 방향 |
|---|---|
| 소음기 | 발사음과 총구 섬광 감소, 유효 사거리 조정 |
| 소염기 | 총구 섬광 감소, 반동 보정 |
| 배율 렌즈 | 조준 배율 및 ADS 시야각 변경 |
| 탄창 | 장탄 수와 재장전 속도 변경 |
| 수직 손잡이 | 수직 반동 감소 |
| 보조 손잡이 | 수평 반동 및 조준 흔들림 감소 |

소음기와 소염기는 동일한 총구 슬롯을 사용하여 동시에 장착할 수 없게 한다. 파츠 효과를 무기 코드에 직접 고정하지 않고 데이터 기반 Modifier로 합산하며, 서버가 장착 가능 슬롯과 최종 무기 능력치를 검증한다.

### 3.8 사망 및 리스폰

- 체력이 0이 되었을 때 서버에서 사망 처리
- 사망한 캐릭터의 이동 및 공격 제한
- 처치자와 사망자 정보 기록
- 일정 시간 후 Spawn Point에서 리스폰
- 리스폰 시 체력과 탄약 초기화

### 3.9 게임 상태 및 UI

- 플레이어 체력과 탄약 표시
- 제한 시간 표시
- 플레이어별 Kill 및 Death 기록
- 팀별 Kill 및 팀 점수 기록
- 간단한 Kill Feed 표시
- 게임 종료 시 승패 또는 최종 점수 표시
- 회복 아이템 보유 수량, 사용 상태 및 재사용 대기시간 표시
- 장착한 방어구 및 무기 파츠 표시
- 피격 방향과 피격 부위 피드백 표시

## 4. 클래스별 역할

### GameMode

- 서버에서만 존재
- 최대 접속 인원 6명 및 플레이어 접속 처리
- 플레이어 팀 배정과 팀별 Spawn Point 선택
- 플레이어 리스폰 처리
- 게임 시작과 종료 조건 관리
- 팀 승패 판정

### GameState

- 모든 클라이언트에 공유할 게임 상태 관리
- 제한 시간 및 경기 진행 상태 관리
- 팀별 점수와 팀 구성 정보 관리

### PlayerState

- 개별 플레이어의 이름, 팀, Kill, Death 및 개인 점수 관리
- 캐릭터가 사망하고 다시 생성되어도 유지해야 하는 정보 보관

### PlayerController

- 로컬 플레이어 입력 처리
- HUD 및 메뉴 관리
- 서버에 필요한 플레이어 요청 전달

### Character

- 1인칭 이동, 조준, 체력, 피격 부위 및 사망 상태 관리
- Capsule·Skeletal Mesh 충돌 설정 및 사망 시 물리 상태 전환
- 장착 무기 참조
- 방어구 파츠와 회복 아이템 보유 상태 관리
- 다른 클라이언트에 필요한 상태 복제

### Weapon

- 발사 간격, 탄약 및 재장전 관리
- 서버 발사 요청과 검증
- Line Trace 또는 발사체 생성
- 발사 이펙트와 사운드 재생 요청
- 무기 파츠 장착과 최종 능력치 계산

### Consumable Item Component

- 회복 아이템 획득, 사용 요청 및 보유 수량 관리
- 서버 사용 조건과 회복량 검증
- 아이템 사용 상태와 재사용 대기시간 동기화

### Equipment Component

- 방어구 및 무기 파츠 슬롯 관리
- 파츠 장착 가능 여부 검증
- 장비 Modifier를 캐릭터와 무기 능력치에 반영

## 5. 기본 네트워크 처리 원칙

### 서버에서 처리할 항목

- 실제 피격 판정
- 캐릭터 충돌과 Ragdoll 전환 등 물리 상태 판정
- 데미지 적용
- 체력 변경
- 사망 판정
- Kill 및 Death 점수 변경
- 처치자의 팀 점수 변경
- 팀별 승패 판정
- 리스폰
- 경기 시작 및 종료 판정
- 부위별 데미지와 방어구 피해 감소 계산
- 회복 아이템 사용 가능 여부와 회복 효과 적용
- 방어구 및 무기 파츠 장착 검증

- 플레이어 상태와 점수

- 회복 아이템 사용 결과와 보유 수량
- 장착 파츠와 필요한 외형 변경

## 6. 예상 구현 흐름

```text
로컬 플레이어가 발사 입력 수행
→ PlayerController 또는 Character가 Weapon에 발사 요청
→ Weapon이 Server RPC 호출
→ 서버가 탄약과 발사 간격 검증
→ 서버가 Line Trace 수행
→ 서버가 피격 대상과 부위 판정
→ 서버가 데미지 적용
→ 체력 변경 결과 Replication
→ 모든 클라이언트에서 피격 결과와 UI 갱신
```

클라이언트가 최종 데미지 값이나 사망 여부를 직접 결정하지 않도록 구성한다. 클라이언트는 행동을 요청하고, 서버가 해당 요청의 유효성을 확인한 뒤 결과를 결정한다.

## 7. 단계별 진행 계획

개발은 멀티플레이 핵심 루프를 가장 먼저 완성한다. 파츠 시스템은 접속, 전투, 사망, 리스폰 및 경기 진행이 네트워크 환경에서 안정적으로 동작한 이후에만 착수한다.

### 1단계: 네트워크 기초 환경

- 멀티플레이 테스트 프로젝트 또는 테스트 맵 구성
- 서버 1개와 클라이언트 최대 6개 실행
- 2개 팀 구성과 팀별 Spawn Point 설정
- Net Mode 및 Authority 로그 작성
- 이동과 회전 동기화 확인
- 1인칭 카메라, 로컬 팔 Mesh 및 원격 전신 Mesh 구성

완료 기준:

- 최대 6명의 플레이어가 2개 팀으로 접속하고, 각 플레이어가 1인칭 시점으로 조작된다. 상대 화면에서는 전신과 조준 방향이 정상적으로 보인다.

### 2단계: 캐릭터 상태 동기화

- 위치와 회전 동기화 확인
- 조준, 앉기 및 이동 상태 동기화
- 체력 변수 Replication
- 소유 클라이언트와 원격 Proxy 표현 구분
- 접속 및 퇴장 시 상태 정리

완료 기준:

- 서버와 최대 6명의 클라이언트에서 플레이어의 이동·조준·체력 상태가 일치하고, 팀 정보와 접속·퇴장이 정상 처리된다.

### 3단계: 서버 권한 기본 전투

- Hitscan 무기 1종 구현
- Server RPC를 통한 발사 요청
- 서버 Line Trace 및 데미지 적용
- 피격 결과 동기화
- 탄약 소모 및 발사 간격 검증
- 재장전 상태와 결과 동기화
- 발사·재장전 중복 요청 방지

완료 기준:

- 어느 클라이언트가 발사해도 서버가 피격과 탄약을 판정하고 모든 화면에서 동일한 결과가 표시된다.

### 4단계: 사망과 리스폰

- 서버 사망 판정
- Kill 및 Death 기록
- 입력 제한 및 사망 표현
- 리스폰 타이머와 캐릭터 재생성
- 리스폰 시 체력과 탄약 초기화

완료 기준:

- 처치 결과와 팀 점수가 모든 플레이어에게 동일하게 보이며 사망한 플레이어가 자신의 팀 Spawn Point에서 정상적으로 리스폰한다.

### 5단계: 경기 흐름과 UI (이번 8주 범위 제외)

- 제한 시간과 경기 상태 동기화
- HUD, 점수판 및 Kill Feed
- 경기 시작과 종료 처리
- 최종 점수 및 승패 표시

완료 기준:

- 접속부터 전투, 처치, 리스폰 및 경기 종료까지 하나의 멀티플레이 흐름으로 동작한다.

이번 8주 범위에서는 경기 종료 UI와 점수판을 구현하지 않고, 팀 점수는 서버 로그와 PlayerState/GameState 값으로만 확인한다.

### 6단계: 네트워크 환경 테스트 (이번 8주 범위 제외)

- 인위적인 Ping 환경에서 테스트
- Packet Loss 환경에서 테스트
- 중복 RPC 및 연사 요청 확인
- 서버와 클라이언트 로그 비교
- 접속 해제와 재접속 예외 확인
- 발견된 동기화 문제 정리

완료 기준:

- 주요 상태 불일치 사례와 원인을 문서화하고, 핵심 멀티플레이 문제를 수정한다.

### 7단계: 부위별 데미지

- 머리, 상체, 팔·손 및 다리 피격 판정
- 부위별 데미지 배율 데이터 구성
- 서버 기준 최종 데미지 계산

완료 기준:

- 같은 무기로 공격해도 피격 부위에 따라 서버에서 계산된 피해량이 달라지고 모든 클라이언트에 동일하게 반영된다.

### 8단계: 회복 아이템

- 회복 아이템 획득 및 사용 구현
- 서버 사용 조건, 회복량 및 재사용 대기시간 검증
- 피격·이동·사망 시 사용 취소 및 상태 동기화
- 아이템 수량과 사용 상태 표시

완료 기준:

- 각 플레이어가 회복 아이템을 획득하고 사용할 수 있으며, 서버가 회복량·소모·취소 결과를 판정하고 모든 클라이언트에 동일하게 반영한다.

## 7-1. 8주 진행 일정

이번 일정은 최대 6명 접속과 2개 팀 전투를 기준으로 하며, 5단계 경기 흐름·UI와 6단계 네트워크 환경 테스트는 제외한다. UI는 기능 확인에 필요한 최소 디버그 출력만 사용하고, 네트워크 품질 테스트는 후속 단계로 진행한다.

| 주차 | 주요 작업 | 완료 기준 |
|---|---|---|
| 1주차 | 멀티플레이 프로젝트, 테스트 맵, 서버 1개와 클라이언트 최대 6개 실행, 2개 팀과 팀별 Spawn Point 구성 | 최대 6명이 접속하고 팀별로 생성된다. |
| 2주차 | 1인칭 카메라, 로컬 팔 Mesh, 원격 전신 Mesh, 이동·회전 동기화, Capsule·Physics Asset·Collision Channel 구성 | 팀원과 상대 팀 플레이어의 이동·조준 방향이 보이고, 충돌 채널이 의도대로 분리된다. |

| 7주차 | 머리·상체·팔·다리 부위별 데미지와 배율 데이터 구성 | 서버에서 부위별 피해량이 계산되고 모든 클라이언트에 반영된다. |
| 8주차 | 회복 아이템, 사용 취소, 수량 동기화 및 6인 팀전 통합 검증 | 두 팀이 최대 6명으로 전투하고 회복 아이템의 서버 판정이 동작한다. |

## 11. 예상 위험 요소 및 대응

### 서버와 클라이언트의 역할 혼동

각 기능을 구현하기 전에 실행 주체를 서버, 소유 클라이언트 및 전체 클라이언트로 구분한다. Authority와 Net Mode를 로그에 표시하여 실행 위치를 확인한다.

### RPC의 중복 또는 과도한 호출

Tick에서 RPC를 호출하지 않고, 발사와 재장전 같은 명확한 이벤트에만 사용한다. 서버에서 발사 간격과 탄약을 다시 검증한다.

### UI 수치 불일치

클라이언트가 예상값을 직접 확정하지 않고, Replicated 변수 또는 OnRep 함수를 통해 서버 결과로 UI를 갱신한다.

### 범위 확대

첫 결과물은 캐릭터 1종, 무기 1종, 회복 아이템 1종, 테스트 맵 1개 및 최대 6명의 플레이어로 제한한다. 2개 팀의 이동·사격·피격·사망·팀 점수·리스폰을 먼저 완성한 뒤, 부위별 데미지와 회복 아이템을 추가한다. 경기 종료 UI, 네트워크 품질 테스트, 방어구와 무기 파츠는 후속 개발로 분리한다.

### 1인칭 Mesh 및 애니메이션 불일치

소유 클라이언트용 팔 Mesh와 원격 플레이어용 전신 Mesh를 분리하고, 무기 소켓과 조준 방향의 기준을 명확히 한다. 초기에는 복잡한 전신 IK보다 발사 방향과 표현 일치를 우선 검증한다.

### 장비 조합에 따른 수치 복잡도

기본값과 파츠 Modifier를 DataAsset으로 분리하고 최종 능력치는 서버에서 한 번만 계산한다. 합연산과 곱연산의 적용 순서를 문서화하여 클라이언트 표시값과 서버 판정값의 차이를 방지한다.

## 12. 후속 과제 후보

5. 캐릭터 이동 및 애니메이션 네트워크 최적화
6. Dedicated Server 패키징 및 접속 테스트

## 13. 최종 목표

이번 1차 과제의 최종 목표는 온라인 FPS 전체를 제작하는 것이 아니다. 서버 경험이 없는 상태에서 Unreal Engine 멀티플레이의 핵심 구조를 이해하고, 다음 조건을 만족하는 최대 6인 2팀 FPS PvP 전투를 완성하는 것이다.

> 최대 6명의 플레이어가 2개 팀으로 1인칭 시점에 접속하여 이동·사격하고, 서버가 판정한 피격·사망·팀 점수·리스폰 결과를 동일하게 확인할 수 있다.

이 최소 팀전 플레이 흐름이 최대 6명 환경에서 동작하면 1차 과제를 완료한 것으로 판단한다. 이후 2차 확장으로 경기 종료 UI와 네트워크 품질 테스트를 적용하고, 파츠 시스템은 마지막 후속 단계에서 개발한다.

# Project_Z 기능 우선 일정 재산정안

## 1. 문서 목적

이 문서는 2026년 10월 16일 기준 Project_Z FPS 멀티플레이 과제의 실제 구현 상태를 기존 직무과제계획서와 대조하고, 2026년 10월 28일까지 핵심 기능을 완료하기 위한 작업 순서와 완료 기준을 재정리한 문서이다.

- 기준 계획서: `박종호B_직무과제계획서.md`
- 기준일: 2026-10-16
- 목표 완료일: 2026-10-28
- 개발 방향: 기능 완성을 우선하고 무기 위치·카메라·애니메이션 강도 등 연출 조정은 후순위로 진행한다.

## 2. 확정된 범위 변경

### 2.1 발사 판정 방식

기존 계획의 `서버 Hitscan 판정`은 구현하지 않는다. 현재 Project_Z 구조와 구현 결과에 맞춰 다음 방식으로 확정한다.

> 서버 권한 Projectile 충돌 및 피해 처리 연결, 조준 방향·피격 대상·장애물 차단 테스트

Projectile 방식의 완료 기준은 다음과 같다.

- 발사 요청은 소유 클라이언트에서 서버 RPC로 전달한다.
- 서버가 발사 가능 상태, 재장전 상태, 발사 간격 및 탄약을 검증한다.
- 서버가 오브젝트 풀에서 Projectile을 획득하고 발사한다.
- Projectile 충돌과 피해 판정은 서버에서 처리한다.
- 호스트와 원격 클라이언트에서 피해량, HP 및 탄약 상태가 일치한다.
- 장애물에 충돌한 Projectile은 장애물 뒤의 플레이어에게 피해를 주지 않는다.
- Projectile 수명 종료 또는 충돌 완료 후 오브젝트 풀로 정상 반환된다.

### 2.2 연출 작업 우선순위

다음 작업은 핵심 기능 완료 전까지 추가 조정하지 않는다.

- 1인칭 무기 위치 및 회전 세부 조정
- 원격 플레이어 무기 위치 및 손 정렬 조정
- ADS 상태의 카메라 위치와 FOV 세부 튜닝
- AO_Rifle2 적용 강도 및 상·하체 혼합 비율 튜닝
- 총구와 크로스헤어의 시각적 일치 보정

단, 무기가 완전히 보이지 않거나 발사 판정을 확인할 수 없는 등 기능 검증을 방해하는 문제는 최소 범위에서 수정한다.

## 5. 기능 우선순위

### 필수 완료

1. 서버 권한 Projectile 발사·충돌·피해
2. 체력·탄약·재장전 상태 동기화
3. 사망과 리스폰
4. 팀 자동 배정과 팀 정보 복제
5. 팀별 최초 스폰과 리스폰
6. 접속·퇴장 및 최대 6인 관리
7. 6인 및 패킷 손실 환경 검증
8. 설계·오류·검증 결과 문서화

### 기능 검증에 필요한 최소 연출

- 발사·재장전·사망 여부를 식별할 수 있는 최소 애니메이션
- 팀을 구분할 수 있는 최소 UI 또는 시각 표시
- 발사 방향과 피격 여부를 확인할 수 있는 최소 무기·Projectile 표시

### 완료 후 진행

- 1인칭·원격 플레이어 무기 위치 정밀 조정
- 손과 무기의 세부 정렬
- ADS 카메라·FOV 감각 조정
- Aim Offset 강도 및 레이어 혼합 개선
- 총구와 크로스헤어 시각 보정

## 6. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| MultiGameMode가 현재 기본 골격 수준 | 팀·리스폰·접속 관리 일정 증가 | GameMode, GameState, PlayerState 책임을 먼저 확정하고 UI보다 서버 상태 구현을 우선 |
| 사망 상태가 서버 내부 값에만 의존 | 원격 클라이언트의 사망 표현·제한 불일치 | 복제 상태 또는 PlayerState 기반 상태를 정하고 서버 변경만 허용 |
| 6인 환경에서 Projectile·Multicast 증가 | 트래픽 및 풀 고갈 가능성 | 발사 애니메이션은 비신뢰 Multicast 유지, 풀 크기·반환 여부와 네트워크 통계를 확인 |
| 주말 포함 일정에 여유가 없음 | 오류 발생 시 종료일 초과 | 연출 변경 금지, 매일 완료 기준 미달 항목을 다음 날 최우선으로 처리 |
| 계획서와 실제 발사 방식 불일치 | 완료 평가 시 설명 불일치 | 기존 계획서의 Hitscan 표현을 Projectile 충돌 방식으로 공식 변경 |

## 7. 최종 완료 기준

다음 항목을 모두 만족해야 과제의 기능 구현이 완료된 것으로 판단한다.

- Listen Server 환경에서 최대 6명이 접속할 수 있다.
- 서버가 플레이어 팀을 배정하고 모든 클라이언트가 같은 팀 정보를 확인한다.
- 플레이어가 팀별 위치에서 최초 생성되고 사망 후 팀별 위치로 리스폰한다.
- 이동, 발사, Projectile 충돌, 피해, 체력, 탄약 및 재장전 결과가 호스트와 원격 클라이언트에서 일치한다.
- 사망한 플레이어는 이동·발사·재장전을 할 수 없고 리스폰 후 정상 상태로 복구된다.
- 접속·퇴장 시 인원과 팀 정보가 정리되며 최대 인원 초과 접속이 처리된다.
- 패킷 손실 환경에서 치명적인 상태 불일치나 진행 불가 문제가 발생하지 않는다.
- 테스트 결과, 오류 원인, 수정 내용, 재검증 결과 및 잔여 제약이 문서화되어 있다.

## 8. 일정 판단

Hitscan을 제외하고 현재 Projectile 구현을 공식 전투 판정 방식으로 인정하며, 무기·카메라 연출을 후순위로 고정하면 2026년 10월 28일 완료는 가능 범위이다. 다만 주말 4일을 모두 작업일로 사용하고 기능 범위를 추가하지 않는다는 조건이 필요하다.

가장 큰 일정 위험은 사망·리스폰, 팀 배정·팀별 스폰, 접속 인원 관리이다. 따라서 이후 작업은 연출이 아니라 위 기능 순서로 진행하고, 10월 25일까지 기능 구현과 네트워크 시험을 끝내야 한다.
